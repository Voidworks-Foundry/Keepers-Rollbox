# Setup check (`scripts/setup/`)

The Keeper's setup check ([DESIGN.md, "Setup check"](DESIGN.md#setup-check)): a few seconds after the world loads, on the active Keeper's client only, Rollbox looks over the sheets and, if anything needs setting up, shows a notice ("Rollbox: 5 things to set up on 4 sheets.", **Review**). Review opens the list of sheets (each with its count and **Open sheet**), then one question at a time: how a firearm loads (Magazine / 2 rounds at a time / Belt) and an unarmed or maneuver weapon whose skill CoC7 can't find, each with Open sheet, Back and Skip, then Done. A missing Punch or maneuver isn't asked (the Action flyout asks when one is used). **Reload kinds**, from the list and from Done, lists every firearm with its kind, to correct one saved wrongly. Nothing on a sheet changes without a button pressed here; a firearm's kind that the CoC ID table or the name rule is sure of is saved as Rollbox's own flag on the weapon without asking (it is Rollbox's note, not a sheet change). A firearm added to a sheet, or a new actor, is checked when it is added. **Check setup now** in the settings runs it on demand. Players never see any of it. Files: `index.js` (registration, the login check, what is added, Check now, the setting), `scan.js` (the scan: the questions and the kinds saved), `window.js` (the notice and the window), `setup.css` (their look).

User guide: [For Keepers](../guide/for-keepers.md) ("Setup check") and [Settings](../guide/settings.md) (Setup).

**Status key:** *Confirmed* only when the [Internal API registry](DEVELOPING.md#internal-api-registry) says so. The notice at login, the list, every question kind, Skip, Back, Done, Reload kinds, a firearm added mid-session, Check now from Foundry's settings and the setting off were seen working in Foundry (build 370) in the end-to-end check; still **Assumed** until checked at the table.

## Code

### `registerSetupCheck()`; private `SETUP_DELAY_MS` (`index.js`)
- **How it works:** At ready (`main.js`, after the other parts), on a Keeper's client only (`isKeeper`): hooks `createItem` (`itemAdded`) and `createActor` (`actorAdded`), and a timer of `SETUP_DELAY_MS` (4 s), so the check runs after Foundry's own startup work, then `checkAtLogin`. A player's client registers nothing. Returns `true` when registered.
- **Connects to:** `main.js` (`start("the setup check", …)`); `checkAtLogin`, `itemAdded`, `actorAdded`.
- **Could interact poorly with:** a world that is still loading heavy scenes 4 s after ready: the scan only reads data Foundry already holds, so it is quick either way (about 1 ms on the demo world's 66 sheets). **Assumed.**

### `checkAtLogin()`, `checkNow()` (`index.js`)
- **How it works:** `checkAtLogin`: only on the active Keeper's client (`isActiveKeeper`, so two Keepers never both ask) and with `rollboxSetupCheck` on: `scanSetup()` over every sheet, then `showNotice(issues)` (nothing when there is nothing to set up). `checkNow`: on any Keeper's client, whatever the setting: `scanSetup()`, then `openWindow(issues, { ms })` (the list, or Done with "Nothing to set up." when there is nothing).
- **Connects to:** `scan.js` `scanSetup`; `window.js` `showNotice`, `openWindow`; the Check now menu (`checkNowMenuType`).
- **Could interact poorly with:** nothing known. **Assumed.**

### `itemAdded(item)`; private `actorAdded`, `checkAddedSoon`, `added`, `ADDED_DELAY_MS` (`index.js`)
- **How it works:** `createItem` with a firearm Rollbox reloads (`shared/` `isReloadable`) on a sheet, and `createActor` with an investigator, NPC or creature (`roll-requests/` `actorKind`), on the active Keeper's client with the setting on, wait `ADDED_DELAY_MS` (1.5 s, so a batch of additions makes one notice), then scan those sheets and show a notice with only what was added: a new sheet's every question, a new firearm's own question (its sheet's other questions wait for the next full check). Weapons Rollbox adds itself (Punch, a maneuver) aren't firearms, so adding one never raises a notice mid-fight.
- **Connects to:** Foundry's `createItem` and `createActor` hooks; `scanSetup`, `showNotice`.
- **Could interact poorly with:** importing many actors at once: one notice for all of them. **Assumed.**

### `registerCheckNowMenu()`, `CHECK_NOW`; private `checkNowMenuType` (`index.js`)
- **How it works:** At init (`settings.js` `registerSettings`): `game.settings.registerMenu("keepers-rollbox", "rollboxSetupCheckNow", { name: "Check setup now", label: "Check now", icon, type, restricted: true })`. Foundry requires a menu's `type` to be an `ApplicationV2` (or FormApplication) subclass and opens it with `new type().render(true)`; `checkNowMenuType` returns a subclass of Foundry's `ApplicationV2` whose `render` runs `checkNow()` and draws no window of its own. Null (and no menu) without Foundry's `ApplicationV2`.
- **Connects to:** Foundry's `ClientSettings#registerMenu`, `SettingsConfig` (`openSubmenu`); `settings.js`, which puts the button in the Setup check section (its `menus`) and gives it its scope note (`CHECK_NOW.note`).
- **Could interact poorly with:** a Foundry that stops accepting an `ApplicationV2` subclass as a menu type: registering throws, one warning, no button. **Assumed.**

### `scanSetup(actors)`, `setupActors()`, `skipForNow(issue)`, `firearmKinds(actors)` (`scan.js`); private `actorIssues`, `skippedNow`
- **How it works:** `setupActors`: world actors that are investigators, NPCs or creatures (or carry a firearm), then the current scene's unlinked tokens' own sheets. `scanSetup` → `{ issues, saved, ms }`. Per sheet (`actorIssues`): each firearm (`isReloadable`): its kind (`reloadSource`: flag, CoC ID table, name rule, guess); a kind from the table or a sure name rule is saved (`flags.keepers-rollbox.reloadKind`), one `updateEmbeddedDocuments("Item", …)` per actor; a guess is a `reload` question with the guess. No question about a missing Punch or maneuver (the Action flyout's prompts ask at use). A sheet with a fighting skill: its unarmed weapon or a maneuver weapon whose skill CoC7 can't find (`skillUnset`) is a `skill` question. A weapon carrying Rollbox's `maneuverOff` flag (its Maneuver switched off for a fight back and never switched back on: the page closed in that second; roll-requests `maneuver.js`) is switched back on (`system.properties.mnvr: true`, the flag removed with utils' `flagsRemoved`) in the same per-sheet update; no question. Each question has a `key` (`<actor uuid>|<kind>|<item id>`) and `ask` (its kind). Skipped (`skipForNow`) keys are left out until the page is reloaded. `ms` is how long the look took, without the saving. A sheet that can't be read is one warning and skipped. `firearmKinds`: every firearm on those sheets with `{ actor, weapon, kind, source }` (`reloadSource`: "flag", "cocid", "rule" or "guess"), for the Reload kinds list.
- **Connects to:** `roll-requests/` (`actorKind`, `unarmedOnSheet`, `isManeuverWeapon`, `skillUnset`, `fightingSkill`, `MANEUVER_OFF_FLAG`, [roll-requests.md](roll-requests.md)); `utils.js` (`flagsRemoved`, `warn`); `shared/` (`isReloadable`, `reloadSource`, `RELOAD_FLAG`, [shared.md](shared.md)); Foundry's `game.actors`, `canvas.scene.tokens`, `Actor#updateEmbeddedDocuments`, `Document#getFlag`/`setFlag`.
- **Could interact poorly with:** another module that also writes `flags.keepers-rollbox` (none should). An unlinked token's sheet is checked apart from its world actor, so a world actor fixed doesn't fix tokens already placed. **Assumed.**

### `showNotice(issues)`, `closeNotice()`, `openWindow(issues, { ms })`, `closeWindow()` (`window.js`); private `countText`, `draw`, `saving`, `notSaved`, `listView`, `stepView`, `doneView`, `kindsView`, `kindsButton`, `kindRow`, `finish`, `move`, `bySheet`, `sheetRow`, `progress`, `portrait`, `openSheet`, `who`, `typeText`, `KIND_LABELS`, `KIND_SHORT`, `TYPE_LABELS`
- **How it works:** Rollbox's own boxes in Foundry's `#interface` (or the page), each `rollbox-panel` with the panel's look (`panel/` `followTheme`). The notice (`.rollbox-setup-notice`, top centre): "**Rollbox:** N things to set up on M sheets." (`countText`), **Review** (opens the window) and ✕. The window (`.rollbox-setup`, `data-view` list, step, done or kinds; `data-scan-ms` from Check now): a header "Rollbox setup check" with ✕; **list**: "N things to set up on M sheets. Only you see this. Answers Rollbox was sure of are already saved; these questions wait for your OK." (the scan saves sure answers itself, `scanSetup`), a row per sheet (portrait, name, type, "token on this scene" for an unlinked token, the count, **Open sheet**: CoC7's own sheet), **Later**, **Reload kinds** and **Review one at a time**; **step**: "i of N" with a dot per question, the sheet's row with Open sheet, the question, then **Back**, **Skip** and the main button: `reload` "How does X load?" with "Rollbox couldn't tell from its name or skill (skill, holds N). Reloading in combat follows this." and Magazine / 2 rounds at a time / Belt (the guess picked), **Save and next** (`saveReloadKind`); `skill` "Punch has no skill set", "CoC7's attack card can't roll without it. Links it to Fighting (Brawl) (40%).", **Fix and next** (`setWeaponSkill`). The last step's button says "… and finish". **done**: each sheet with Done, Skipped or Not yet, "Setup looks good. New weapons and characters are checked when they're added.", **Reload kinds** and **Close**; **kinds** (`firearmKinds`): "How each firearm reloads in combat. Press a kind to correct it; it is saved at once.", a row per firearm (portrait, the weapon, whose it is, "· a guess" when only the name rule guessed, then Magazine · 2 rounds · Belt with the kind read now checked); a press saves it with `saveReloadKind` and redraws; **Back** (to where it was opened) and **Close**. A save that fails (its function returns false or throws: `saving`, which also lets only one save run at a time) leaves the step or list as it was and shows a message in the window, `.rollbox-setup-error` (`role="alert"`, the panel's `--rollbox-bad` colour): "Couldn't save this on X. Try again, or open the sheet to set it by hand." (`notSaved`), until the next redraw; Rollbox's console warning gives the cause.
- **Connects to:** `shared/` (`button`, `RELOAD_KINDS`, `saveReloadKind`, one import of `shared/index.js`); `roll-requests/` (`setWeaponSkill`); `scan.js` (`skipForNow`, `firearmKinds`); `panel/` (`followTheme`).
- **Could interact poorly with:** Foundry's notifications at the top centre: the notice sits below them (`top: 64px`). **Assumed.**

### `setup.css`
- **How it works:** Listed in `module.json` `styles`. The notice and window are fixed, centred, above windows (`--z-index-window` + 40); the window 340px wide, at most 76% of the screen tall, its list scrolling. Colours from the panel's palette (`--rollbox-*`), so the Art Deco and CoC7 minimal themes draw them in their own colours; their files add the page texture or shadow and the title font.
- **Could interact poorly with:** nothing known. **Assumed.**

## Hooks, overrides, keybindings
- `createItem`, `createActor` (a Keeper's client): what is added is checked.
- No overrides; no keybindings.

## Settings
Declared here (`SETTINGS`, `CHECK_NOW`); `settings.js` puts `rollboxSetupCheck` (**Setup check at login**) among the feature switches on top and the Check now button in the **Setup check** section, which greys out while the switch is off (display only: Check now runs whatever the switch says).

| Key | Kind | Default | Label | Note |
| --- | --- | --- | --- | --- |
| `rollboxSetupCheck` | world Boolean | on | Setup check at login | Keeper setting, applies to everyone. |
| `rollboxSetupCheckNow` | settings menu (button **Check now**) | — | Check setup now | Keeper setting, applies to everyone. |

## Flags
- `flags.keepers-rollbox.reloadKind` on a firearm item (`magazine` | `rounds` | `belt`): see [shared.md](shared.md).
- `flags.keepers-rollbox.maneuverOff` on a weapon item (`true` while Rollbox has its Maneuver switched off for a fight back): cleared here (in the same update as Maneuver back on, with Foundry v14's `ForcedDeletion` through utils' `flagsRemoved`); see [roll-requests.md](roll-requests.md).
- `flags.keepers-rollbox.setupSkip` on an actor: neither read nor written by Rollbox (it held a creature's "Don't ask again" for a question the check doesn't ask); a world that holds it keeps the data.
