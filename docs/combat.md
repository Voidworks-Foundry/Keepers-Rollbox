# Combat (`scripts/combat/`)

Combat in the character panel. While Foundry runs an encounter, the panel shows everyone in turn order with the turn controls under it. This part also starts a fight when someone attacks and decides who joins it (standing by included), manages readied firearms, keeps per-round notes, posts the weapon-drawn card and the flee notice, and reads what the board says about an attack (firing into melee, an outnumbered target). Rollbox reads Foundry's combat and moves turns only through Foundry's own `Combat` and `Combatant` methods. CoC7's initiative and Draw gun stay CoC7's: Rollbox only presses CoC7's own Draw gun button in the combat tracker, a toggle CoC7 offers in its own UI. What the Keeper and players see: [the user guide, For Keepers](../guide/for-keepers.md); the rules: [DESIGN.md, "Combat"](DESIGN.md#combat).

`main.js` calls `registerCombat()` at `ready`, after the panel; `combat.css` is in `module.json`. `index.js` re-exports, for other parts (the Action flyout, the being-attacked alert and its other tabs, `settings.js`): the Gameplay switch's settings (`GAMEPLAY_SETTINGS`), the round notes (`roundNote`, `markNote`, `markAiming`, `markDived`, `markActed`, `markAttack`, `isAiming`, `hasDived`, `hasActed`, `attacksMade`, `clearAiming`, `NOTES_FLAG`), the weapon-drawn notice (`postNoticeCard`), readied firearms for the Action flyout's holster warning (`drawnGun`, `readiesAsFirearm`), About to attack (`aboutToAttack`, `asksFirst`, `surprisedBy`, `surpriseOf`, `clearSurprise`), the fight (`attackMade`, `spellCastAt`), the attack situation (`attacksPerRound`, `inMeleeWithOthers`, `isOutnumbered`), the players' wait (`keeperDeciding`; `holdWhileDeciding` on a player's client with a panel: the panel's `setPlayerHold` greys their whole menu but Action, "Waiting for the Keeper", redrawn on `updateScene` when Rollbox's scene flags change), and every combat setting list for `settings.js` (`GAMEPLAY_SETTINGS`, `FIGHT_SETTINGS`, `TURN_SETTINGS`, `FIREARM_SETTINGS`, `NOTICE_SETTINGS`, `DRAW_SETTINGS`, `NOTICE_PLACE_SETTINGS`). Other parts import combat only through `index.js`, `settings.js` included.

**Status key:** *Confirmed* only when the build guide's Internal API registry ([DEVELOPING.md](DEVELOPING.md), "Internal API registry") says so; "Seen in e2e" means the end-to-end check in a running Foundry showed it working and it waits for the table. Everything else is **Assumed**.

## Code

### `encounter.js`: `runningCombat(concerned)`, `viewedCombat()`, `startedCombatant(id)`, `turnsOf(combat)`, `combatantFor(actor, combat)`, `isCombatantOf(combatant, actor)`, `currentCombatant(combat)`, `roundOf(combat)`, `gameplayOn()`, `SETTINGS`; private `startedCombats`, `sceneIdsOf`, `holds`, `preferred`, `tokenDocOf`
- **How it works:** two readings of Foundry's encounters. **The rules** read `runningCombat(concerned)` → `Combat | null`, whatever scene the Keeper is viewing: of every started encounter (`game.combat` and `game.combats`), the one holding one of the characters or tokens concerned (a token by its own combatant, a character by `isCombatantOf`), else one on their scene (a token's own scene; a character's scenes from Foundry's `Actor#getDependentTokens()`), else **none** (an encounter on another scene is not theirs); with nobody given, or a scene that can't be told, any started one. Of several, `preferred` takes the viewed one (`game.combat`), Foundry's active one (`game.combats.active`), the active one on the players' scene (`game.scenes.active`), any active one, then the first. **The panel** reads `viewedCombat()` → `game.combat` when it has started and is on the viewed scene (an encounter with no scene counts everywhere): the turn order, the pick in it, the turn's token selected, the Keeper acting for the current turn with nothing selected, a player's "Waiting for the Keeper". `startedCombatant(id)` finds a combatant in any started encounter (the relay's answers name only its id). `turnsOf(combat)` → `Combat#turns` as an array. `combatantFor(actor, combat)` and `isCombatantOf(combatant, actor)` match by object or by `uuid`, so a token's own actor matches too. `currentCombatant(combat)` → `Combat#combatant`. `roundOf(combat)` → `Combat#round` as a number (0 before it starts). Every read is guarded: a missing or odd `game.combat` reads as no encounter. `SETTINGS` declares `rollboxGameplay`, the Gameplay section's master switch (world, Keeper, default on); `gameplayOn()` reads it. Every combat file reads the encounter from here, so none imports `index.js`.
- **Connects to:** Foundry's `game.combat`, `game.combats` (and its `active`), `game.scenes.active`, `Combat#started`, `#active`, `#scene`, `#turns`, `#combatant`, `#combatants` and `#round`, `Actor#getDependentTokens`, plus `canvas.scene` (all public); `utils.js` (`declareSettings`, `option`). Every rule in `combat/` and the Action flyout's combat checks (`inCombatFor`, `currentTurn(actor)`, `inCombat(actor)`) pass the characters concerned.
- **Could interact poorly with:** modules that replace Foundry's combat tracker or turn order (`Combat#turns`). Two encounters started at once with the same linked character in both: the viewed, then the active one is read. **Seen in e2e** (a fight on the demo scene with the Keeper on another scene: the standing-by turn skipped, Unconscious marked defeated, a player's relayed attack joining it).

### `index.js`: `inCombat(concerned)`, `inCombatFor(actor)`, `currentTurn(actor)`, `registerCombat()`, and the exported hook handlers `onCombatUpdate`, `onCombatantUpdate`, `onCombatGone`, `onTurnChange`, `onDelayedTurn`, `onDelayedTurnChange`; private `showCombat`, `idleActors`, `turnWork`, `turnQueue`, `queueTurnWork`, `delayed`, `onPickChanged`, `willSkip`, `selectCurrentToken`, `followNewTurn`, `onTokenSelected`, `onCombatDeleted`, `onActorChanged`, `registerGameplay`, `registerTurnOrder`
- **Interface:** `inCombat()` → `boolean`. `inCombatFor(actor)` → `boolean`: an encounter runs and the character has a combatant in it (the Action flyout counts a character outside it, fled or never joined, as out of combat). `currentTurn()` → `{ actor, token } | null`. `registerCombat()` → `boolean`: `false` only on a player's client with the Player Rollbox off, where nothing is installed.
- **How it works:** `registerCombat()` installs two halves separately.
  - **Gameplay rules**, on the Keeper's client whatever the Keeper's "Rollbox panel" switch (`registerGameplay`): `updateCombat` (`onCombatUpdate`: every turn or round change is queued, `turnQueue`, and handled after the one before has finished, `turnWork`: a new round clears the round notes, carrying Aiming over once, then puts delayed combatants back, `restoreDelayed` (one `Combat#updateEmbeddedDocuments("Combatant")` call for all of them, initiative and `delayedFrom` removal together, `combatTurn: 0` at the top of the round), then readies the guns, each awaited before the next, putting someone back and readying a gun both move the turn order, and the guns go last so the round starts at the top of the order they leave; then `fight.js` `onTurn`: who is in the fight and one skipped turn. Rollbox's own skip's `updateCombat` carries its update option `rollboxOwnStep` (`OWN_STEP`) and is queued as the next turn start; the option travels with that one update, so another update arriving while the skip is awaited is never taken as Rollbox's own. One queue because two handlers that each move the turn raced: a skip already on its way moved the turn past a readied shooter just put at the top, who lost his turn), `updateCombatant` (`onCombatantUpdate`: a confirmed Delay, its `delayedFrom` flag set this round, is queued as a turn start, since Foundry gives the turn through that update's `combatTurn` with no `updateCombat`, so who is in and a skipped turn run for the next person; CoC7's Draw gun turned on for someone standing by makes them a fighter, `fight.js` `onGunDrawn`; anyone's `standingBy` set puts their gun away, `fight.js` `onStandingBy`), `deleteCombat` (`onCombatGone`: forgets the picks seen, clears the notes, and closes the Keeper's boxes about the fight: the joining card, Who's joining this fight? as its Cancel does, so the First blow card comes back, and the flee notice), `updateActor` (`onPickChanged`: a picked weapon may un-ready a gun), `updateChatMessage` (`defenderAnswered`, `situation.js`: a defence on CoC7's defender card is noted for outnumbered), the weapon-drawn notice's relay message (`registerNoticeCards`: relay `notice`), About to attack's relay message (`about-to-attack.js` `registerAboutToAttack`: relay `aboutToAttack`), the fight's relay message (`fight-relay.js` `registerFight`: relay `fight`; the fight's turn rule runs in the queue above), the defeated marks (`defeated.js` `registerDefeated`), each character's own target (`own-target.js` `registerOwnTarget`) and, once at `ready`, a leftover players' wait taken off (`waiting.js` `clearLeftoverWait`). Status's Aiming and Dived for cover are handed the round-note readers when `index.js` loads (`status/` `readRoundNotesWith`, with `isAiming` and `hasDived`), since status can't import combat. Each handler acts only on the active Keeper's client (utils' `isActiveKeeper`: Foundry's `game.users.activeGM`), so a second GM logged in never does the same write or initiative roll twice; forgetting the picks seen runs on every Keeper's client. Readied firearms, the weapon-drawn card, the fight rules and the melee reach read `rollboxGameplay` when they run; clearing the round notes and putting delayed combatants back run whatever the switch, since they are bookkeeping, not a rule.
  - **The turn order**, wherever a panel is (`player/` `panelHere()`: the Keeper's with the switch on, or a player's with the Player Rollbox on): `updateCombat`, `createCombat`, `createCombatant`, `updateCombatant`, `deleteCombatant`, `canvasReady` (redraw), `deleteCombat` (`onCombatDeleted`: the turn-control state goes, the panel's own content comes back) and `updateActor` (`onActorChanged`: round notes on the rows; only for a character with a combatant in the running encounter, so anyone else's change draws nothing); it shows the turn order at once if an encounter is running.
  - On a player's client every redraw also shows or closes their join card (`fight-relay.js` `syncJoinCard`).
  - **Selection follows the turn** (the Keeper's panel only): `updateCombat` → `onTurnChange`: at a turn or round change the pick in the turn order is forgotten (`turn-pick.js` `followTurn`); with the personal setting `rollboxTurnSelection` on `select` (the default; `turn-order.js` `selectsTurn`), the current turn's token is selected on the map in the turn change's own hook (`followNewTurn` → `selectCurrentToken`: `Token#control({ releaseOthers: true })`, as a click; released with `TokenLayer#releaseAll` when the token isn't on this scene), before the panel's next frame, so the panel draws the new turn once (a later selection would draw the old selection's layout for a frame first). A confirmed Delay's `updateCombatant` (`onDelayedTurn`) comes before Foundry re-sorts, so it only marks `delayedTurn` and the selection is made in `combatTurnChange` (`onDelayedTurnChange`). A turn Rollbox's gameplay skips at once (`willSkip`: Gameplay on, `fight-state.js` `skipsTurn`, someone still acting) selects nothing and marks `followsSkip`, so the skip's own turn change follows the turn even in round 1; on `keep` the Keeper's selection is never touched and the panel follows the turn only while nothing is selected. Not for the update that starts the encounter (round 1, turn 0: the Keeper's Start combat keeps their flyout and result) nor for Rollbox's own `rollboxKeepTurn` update; Place on standby's turn update (option `rollboxEndsTurn`, `fight-state.js` `ENDS_TURN`) always counts, also in round 1. `updateCombatant` → `onDelayedTurn`: a confirmed Delay ends the turn the same way (the pick forgotten, the next person's token selected, the delayed one released). `controlToken` → `onTokenSelected`: a token selected on the map takes over from the pick.
  - `showCombat()` puts the panel's own content back (`clearPanelContent`) with no encounter running **or with `rollboxCombatPanel` off** (`turn-order.js` `combatPanelOn`; the panel then works as out of combat, and Foundry's tracker runs the turns; the gameplay rules and a player's join card are unaffected); otherwise it calls `setPanelContent(turnOrderContent, { idleActors })` once when an encounter is running, then only `refreshPanel()` for every later change, so however many hooks fire for one change (a round change updates every combatant's character) the panel redraws once, on its next frame; outside an encounter it calls `clearPanelContent()` and forgets that it provided the content; `idleActors` is the combatant the Keeper picked in the turn order (`pickedCombatant`), else the current turn's character, on the Keeper's client, so with nothing selected the panel still shows the turn order and its menu acts for the pick or whoever's turn it is.
- **Connects to:** `panel/index.js` (`setPanelContent`, `clearPanelContent`, `refreshPanel`), `utils.js` (`isActiveKeeper`), `player/index.js` (`playerRollboxOn`, `panelHere`), `status/index.js` (`readRoundNotesWith`), `turn-pick.js` (`followTurn`, `pickedCombatant`), and the files below; Foundry hooks `updateCombat`, `deleteCombat`, `createCombat`, `create/update/deleteCombatant`, `canvasReady`, `updateActor`, `updateChatMessage`, `combatTurnChange`, `controlToken`; `Token#control`, `canvas.tokens.releaseAll()`.
- **Could interact poorly with:** several Keepers logged in: only Foundry's active GM runs the gameplay rules; with none known, every Keeper does. **Assumed.** The combat hooks: **Seen in e2e.**

### `turn-order.js`: `turnOrder(combat)`, `buildTurnOrder(context)`, `turnOrderContent(actors, { onValue })`, `rowClicked(entry, user, combat, { right })`, `selectsTurn()`, `combatPanelOn()`, `setTurnOrderRedraw(fn)`, `SETTINGS`; private `keeperClick`, `NOTE_TEXT`, `READIED_TEXT`, `CURRENT_CLASS`, `PICKED_CLASS`, `DONE_CLASS`, `STANDBY_CLASS`, `COMPACT_CLASS`, `dexOf`, `outsideCards`, `previewDelay`, `standingBox`, `followStanding`, `scrollIntoList`, `targeting`, `targetEntry`, `releaseSelection`, `addOutside`
- **Interface:** `turnOrder(combat)` → `[{ actor, token, current, done, standing, combatant }]`, Foundry's turn order (`Combat#turns`, the combat tracker's), never rotated, the fighters first, then everyone standing by (`standing`, the current turn too) at the back, highest DEX first (`dexOf`, CoC7's `system.characteristics.dex.value`), equal DEX in Foundry's order (only drawn so: `Combat#turns` and CoC7's initiatives are unchanged, so Remove from standby puts them back in their place); `done`: their turn has passed this round. Combatants with no actor are left out. `turnOrderContent(actors, { onValue })` is the provider for `setPanelContent`: the panel's characters (selected on the map, or with nothing selected the pick or the current turn's) are the Keeper's `focus`; it returns `null` (the panel draws its own content) when no encounter is running or there is no user. `buildTurnOrder({ combat, user, own, focus, onChange, onValue, onRow, onAdd })` does the drawing, or returns `null` with no started encounter or no one to show. The Keeper's pick in the turn order is `turn-pick.js`'s (below). `rowClicked(entry, user, combat)` → `"target" | "pick" | null`. `setTurnOrderRedraw(fn)` is how `index.js` tells the turn controls to redraw the panel.
- **The Keeper's pick** (`pickedCombatant`, `pickCombatant`, `followTurn`) lives in `turn-pick.js`, which the turn order sets and `own-target.js` reads, so neither of those two imports the other.
- **How it works:** the top card is a header, "Combat · Round N". **The order stays put**: the fighters in Foundry's order, the full card in its own place (`groupNodes`: the rows above it in one group card, the rows below in another, `rowsCard`), then **End of round N** (`rollbox-turn-round-end`), then the standing-by group (`rollbox-turn-rows rollbox-turn-standing`, its first card titled "Standing by", `rollbox-turn-standing-title`; a full card first in it gets the heading on its own, `rollbox-turn-standing-heading`). Delay's live preview moves the current fighter down among the fighters only (`previewDelay`). **The Keeper's combat panel**: everyone is a collapsed card (a row); the **selected** combatant (the first of `focus` in the encounter) is the full character sheet (`panel/sheet.js` `characterSheet`) with its status cards above it (`panel/status-cards.js` `statusCards`). The current turn keeps its red outline inside its edge (`CURRENT_CLASS`, `rollbox-turn-current`; `outline-offset: -2px`, so the width never changes), as a sheet or as a row (its row then reads "NPC · current turn" or "<owners> · current turn"); a selected combatant who isn't the current turn has a blue outline and no label (`PICKED_CLASS`, `rollbox-turn-picked`; several selected on the map: the rest are outlined rows). A click on a row (`rowClicked`, "Clicks on a row" below): a target goes to that combatant's token (`Token#setTarget(true, { releaseOthers: true })`, which Foundry's `targetToken` hook passes to a waiting picker: the Action flyout's Target a token, Opposed's and Assist's Pick a target and Add a character, the player's Target who you're helping); the Keeper's select releases the map's selection and picks that combatant (`pickCombatant`; the current turn's row goes back to following the turn), and the panel redraws acting for them. The whole box drags the panel ([panel.md](panel.md), Dragging); a press that doesn't move stays a click. Rows are focusable (Enter or Space as a click). Someone selected on the map who isn't in the encounter (`outsideCards`, Keeper only) shows above the header: "Not in combat" (`rollbox-turn-outside-label`), their full card (others as rows) and **Add to combat ↓** (`rollbox-turn-add`; `addOutside`: the selected tokens of those characters through `fight-changes.js` `addFighters`, which adds them as fighters with CoC7's initiative); the turn controls then keep only End combat (`turnControls({ outside: true })`). A row whose turn has passed this round is a little darker (`DONE_CLASS`, `rollbox-turn-done`, a brightness filter, so every theme's card background keeps its look). Every row: portrait, name, owner or "NPC", "Readied firearm" (`READIED_TEXT`) when CoC7's Draw gun is on, "Defeated" (`defeated.js` `isDefeated`), this round's notes (`NOTE_TEXT`: Aiming, Dived for cover, Stood their ground, Acted, Delayed, Fled), on the Keeper's rows the meters ticked in `rollboxCardMeters` as thin vertical bars (`panel/` `meters`, the character cards' bars without their heading, each bar's hover text naming it, about 12px wide on these rows; a player's rows have none: their own character is their sheet or a standing-by name, and they see no one else's). No initiative number (the order says who goes when; Foundry's tracker still shows it). A player's own character (`player/` `ownCharacter`) is always the full sheet, in its place in the order; the others are rows, and the acting row is outlined. Their character not in the encounter (fled, or never joined) keeps its full sheet, "Not in combat" above it, **under** the header, the order and the controls. Players don't see hidden combatants (`Combatant#hidden`), as in Foundry's tracker. **Standing by** (`fight-state.js`): the row is **compact** (`COMPACT_CLASS`, `rollbox-turn-compact`): the name only, half a row's height, greyed (`rollbox-turn-standby`, italic name); its status ("Standing by", "Standing by · acts this round" or "Standing by · acts next round", `standingText`) and this round's notes are the name's hover text. A standing-by full sheet is greyed with that status in a small card above it. The Keeper's selected standing-by combatant has **Act this round** in the turn controls (`turn-controls.js` `actsButton`, the player's toggle: `askFight("acts")`, which on the Keeper's client sets `actsRound` directly), so the Keeper sets it for a standing-by NPC. **Delay's live preview**: while Delay's arrows are pressed, the current turn's entry is drawn that many places down (`previewDelay` with `turn-controls.js` `delayPreview`), only while the controls act for the current turn (a player, or the Keeper's full card being the current turn's). A player whose own character stands by gets their sheet greyed at the top with the box (`standingBox`): "Standing by" / "Your turn is skipped." (or "You act on your turn this round." / "… next round.") with **Act this round** (`turn-controls.js` `actsButton`, saved by the Keeper's client) and **Rejoin the fight** (`rejoinButton`) on one row (`rollbox-turn-row rollbox-turn-standby-buttons`, the turn buttons' height), or "Your turn" / "Back on standby after this turn." with Rejoin the fight alone when the order stops on them (with a fighter's turn controls); their own character is then a row in the order. The turn controls go last. Built with `textContent` only.
- **The standing-by list scrolls past five**: each standing-by group card's list (`rollbox-turn-standing-list`) is five compact rows and their gaps high and scrolls past that, every theme (`combat.css`; Art Deco and CoC7 minimal restate the row height, 18px and 17px, with a 2px padding so the current row's outline stays inside); the group's title sits outside the list, so it stays put. Each row carries its combatant's id (`data-combatant`). `followStanding(root)`, a tick after drawing (the list needs its layout): each list back to where it was scrolled (module state by the list's place in the group, from its `scroll` events), then the Keeper's picked row in the group, else the acting (current) one, scrolled just into view (`scrollIntoList`, from the two boxes) when it is a different combatant from last time, so a redraw never pulls the list back after the Keeper scrolled away. - **Could interact poorly with (the list):** nothing outside Rollbox: Rollbox's own DOM and CSS. A theme module restyling Rollbox's rows to another height would leave five rows' height wrong. **Assumed.**
- **Values on the sheet:** `onValue` is the panel's own value-click handler; the full sheet passes it on with that sheet's character, so its characteristics, SAN and Luck open flyouts as on the panel's sheet.
- **Connects to:** `panel/index.js` (`characterSheet`, `meters`, `nameLine`, `ownerText`, `portrait`, `statusCards`), `shared/` (`targetOnly`, `tokenFor`), `player/index.js` (`ownCharacter`), `encounter.js`, `readied-firearms.js` (`hasGun`), `round-notes.js` (`noteMarks`), `fight-state.js` (`standingBy`, `actsThisRound`, `actsNextRound`), `fight-changes.js` (`addFighters`), `defeated.js` (`isDefeated`), `own-target.js` (`selectionChanged`), `turn-pick.js` (`pickCombatant`, `pickedCombatant`), `turn-controls.js` (`turnControls` with the Keeper's `selected` combatant, `actsButton`, `rejoinButton`, `delayPreview`); Foundry's `ui.controls.tool` (the active tool's `name`), `Token#setTarget`, `TokenLayer#releaseAll`, `canvas.tokens.controlled`. - **Clicks on a row**: each row listens to `click` (and Enter or Space) and `contextmenu` (its browser menu prevented), both calling `onRow(entry, { right })` → `rowClicked`. A **right click always targets** that combatant's token (`targetEntry`: shared's `targetOnly`, `Token#setTarget(true, { releaseOthers: true })`, on the combatant's token, or for someone outside the encounter shared's `tokenFor`), for the Keeper and players. ### `turn-pick.js`: `pickedCombatant(combat)`, `pickCombatant(combatant, combat)`, `followTurn()`; private `picked`
- **Interface:** `pickedCombatant(combat = viewedCombat())` → the combatant the Keeper picked in the turn order while they are still in that encounter (`Combat#turns`), else `null` (the panel follows the current turn). `pickCombatant(combatant, combat)` sets the pick, or with `null` forgets it. `followTurn()` forgets it.
- **How it works:** module state only, `picked` = `{ combat, combatant }` ids, on the Keeper's client. The turn order sets it (`rowClicked`, the Keeper's select); `index.js` forgets it at a turn or round change, a confirmed Delay, a token selected on the map and the encounter's end, and reads it for `idleActors`; `own-target.js` reads it for whom the Keeper acts for. Its own file so the turn order and `own-target.js`, which the turn order calls, don't import each other.
- **Connects to:** `encounter.js` (`turnsOf`, `viewedCombat`), `turn-order.js`, `index.js`, `own-target.js`.
- **Could interact poorly with:** nothing outside Rollbox: no Foundry or CoC7 call besides reading `Combat#turns`. **Assumed.**

### `notice-place.js`: `placeNotice(card, kind, { handle })`, `noticeStack()`, `forgetNotice(card)`, `resetNoticeSizes(value)`, `SETTINGS`; private `NOTICE_SCALE`, `aboveHotbar`, `placeStack`, `apply`, `putAt`
- **Interface:** `showFightNotice({ …, closeBelow })` puts the ✕ beside the buttons under the line (`rollbox-fight-notice-close-below`, the First blow card). `placeNotice` makes a notice card movable and sizeable and draws it at its kind's saved place and size (`fight-boxes.js` calls it for every card it shows: `joinWindow` (the Keeper's Who's joining this fight?, handle its title row), `joining` (the joining card), `flee`, `chase` (and any other `showFightNotice` kind), `join` (the player's "A fight has broken out"); the handle is the card's top line). `forgetNotice` when a card closes. `noticeStack()` → the stack above the hotbar (made on first use, placed again each call). `resetNoticeSizes` is `rollboxNoticeScale`'s `onChange`.
- **How it works**: a press on the handle (left button, not on a button or input) past 4 px lifts the card out of its stack into Foundry's `#interface` (`rollbox-notice-placed`: `position: fixed`, its spot as inline `left`/`top` from the screen's top left, kept on screen) and it follows the pointer. While the button is held, a capturing `wheel` listener on the window takes every wheel turn (`preventDefault`, `stopImmediatePropagation`, so Foundry's map never zooms, as the panel's own wheel while held): one 10 % step per turn (up is bigger), within 80–250 %, drawn as `transform: scale` from the top left corner.
