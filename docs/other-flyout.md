# Other flyout (`scripts/flyouts/other/`)

The flyout the Other button opens, for any selection. Tabs at the top, like the Check flyout's:

- **The Keeper's:** **Item** (a character's weapons and improvised weapons, exactly one character selected), **Luck** (a Luck check, with the Group Luck roll for two or more; with nothing selected, for every investigator) and **Assist** (Physical Human Limits, two or more; [assist.md](assist.md)). Assist has no button of its own; the Keeper's Opposed is its own menu button ([opposed-flyout.md](opposed-flyout.md)).
- **A player's:** **Opposed** ([opposed-flyout.md](opposed-flyout.md), **Make opposed card**) and **Assist** (helping another character, an NPC or a creature too, [assist.md](assist.md)), each only when the Keeper allows that feature (`canUse("opposed" / "assist")`, `player/index.js`). **No Luck tab** (Keeper Rulebook p. 90: the Keeper calls for Luck rolls): `canUse("luck")` is false for every player. A player picks the opponent, or who they're helping, by targeting a token (`pickTarget`, `player/targeting.js`), since they can't select other characters. While the flyout is registered, an `updateActor` hook draws an open Assist again when an investigator's assist group changes (`assistGroupChanged`, `playerAssistChanged`).

**Last tab used** (the rule for Other): the flyout opens on the tab last chosen (clicked, or opened from the character sheet's Luck) and keeps it while the selection changes. Only Item can be greyed out: it needs exactly one character selected, so with two or more, or nothing selected, it is greyed out and Luck is shown until Item can be used again. **Assist is never greyed out**: with fewer than two characters it offers Add a character (the target picker). With nothing chosen yet, one character opens on Item, and two or more (or nothing selected) on Luck. The flyout's title follows the tab: "Item check", "Luck check", "Assist" or "Opposed roll". A click on the character sheet's Luck opens it on Luck, or sends at once ([panel.md](panel.md), "Clicks on the character sheet's values"; the shortcuts are in [check-flyout.md](check-flyout.md)).

Item and Luck send with the one send button ("Send to <name>", "Send to each (N)", "Send to all players" with nothing selected, or "Roll for NPC(s)"; no Send to chat and no Copy link) through `roll-requests/`, which builds CoC7's own links and rolls NPCs for the Keeper; the flyout builds no request text and rolls nothing itself. The Item tab sends a weapon as an ordinary skill check labelled with the weapon (never CoC7's weapon link, which starts its attack card and ignores the options); it is for a weapon roll with no token to target, such as shooting a lock, and attacks on tokens are the Action flyout's ([action-flyout.md](action-flyout.md)). The Luck tab sends CoC7's Luck attribute check; with nothing selected the Keeper's goes to every investigator (`everyone`, from the menu host), each rolling their own. Registered on the Keeper's client, or a player's with the Player Rollbox on, with the Rollbox switch on. Files: `index.js` (the flyout and its tabs), `item.js` (the Item tab), `luck.js` (the Luck tab), `assist.js`, `assist-split.js`, `assist-group.js` and `player-assist.js` (the Assist tab, [assist.md](assist.md)), `other.css` and `assist.css`; the Opposed tab is `flyouts/opposed/`; the shared controls are [shared.md](shared.md). User guide: [Other](../guide/other.md).

**Status key:** *Confirmed* only when the build guide's Internal API registry or changelog says so. Everything is **assumed** unless stated otherwise. A table check passed for the tabs, the Luck tab, the Group Luck roll and the Item tab.

## What the Keeper sees

| Part | What it shows |
| --- | --- |
| Tabs | **Item**, **Luck** and **Assist** at the top (`role="tablist"`). Item is greyed out (disabled) unless exactly one character is selected (nothing selected included); no help line or tooltip says why ([DESIGN.md, "Flyouts"](DESIGN.md#flyouts): no help lines). Assist is never greyed out |

The Assist tab is [assist.md](assist.md)'s; its Cancel closes Other.

### Luck tab

| Part | What it shows |
| --- | --- |
| Luck | Each selected character's name and "Luck 55", muted (the list scrolls past about 140px). With nothing selected, two short lines instead: "No one selected: this goes to every investigator." and "Select tokens to choose who." |
| Group Luck roll | Two or more selected characters (never with nothing selected), when at least one has a Luck value: a tick box "Group Luck roll: only the lowest Luck rolls". Ticked: "Bob rolls (Luck 35).", or on a tie "Tied at Luck 35. Who rolls?" with one button per tied character |
| How | Difficulty Regular / Hard / Extreme / Hidden and Dice −2 … +2, with the tall Blind toggle beside both rows; then a Label box ("Label (optional), e.g. is the cab still there?") |
| Sending | the line above the button only in red, while the button is greyed out: "Pick who rolls for the group."; one highlighted button, "Send to <name>" ("Send to each (N)", "Send to all players" with nothing selected, or "Roll for NPC(s)" when every character rolling is an NPC); then the result: "Luck check sent to:", "Rolled for you:" or "Not sent:" |

### Item tab (one character)

| Part | What it shows |
| --- | --- |
| Weapons | Each weapon on the sheet, A–Z: its name, below it the skill a request for it uses, and that skill's values on the right. A weapon with two skills (a knife that can be thrown: Fighting (Brawl) and Throw) has a row for each, main skill first. A weapon with no skill set is greyed out and reads "no skill set". A skill missing from the sheet shows its base value. No weapons: "No weapons on Alice's sheet." |
| + Improvised weapon | Last row. Picking it shows, in the same section: "What is it?" (e.g. Candlestick); Skill Brawl (Fighting (Brawl), the default) / Throw / Other… (a list of every skill the character can roll, with values); the chosen skill's name and values |
| Damage (optional) | Improvised only, its own section: the caption, a large editable damage line ([shared.md](shared.md); "0" is no damage), quick-picks None, 1D3+DB, 1D4+DB, 1D6+DB, 1D8+DB, 1D10+DB (the one matching the line shows pressed), and a full-width "Custom damage" button that opens the compact picker with +DB. With Throw picked, the toggle reads "+½DB", the quick-picks "1D3+½DB" … "1D10+½DB", and a DB already on the line becomes ½DB. Simplified dice UI on: only the damage line, no quick-picks and no Custom damage; DB, ½DB or 1/2DB can be typed |
| How | Difficulty Regular / Hard / Extreme / Hidden and Dice −2 … +2, with the tall Blind toggle beside both rows |
| Sending | the line above the button only in red, saying what is missing while the button is greyed out ("Pick a weapon, or an improvised weapon.", "Type what the improvised weapon is.", "Pick the skill it uses.", "Damage is dice, e.g. 1D6, 1D6+2 or 1D6+DB."); no summary; one highlighted button, "Send to <name>" ("Roll for NPC" for a character with no player owner); then the result: "Item check sent to:" and the character, or "Rolled for you:", or "Not sent:" with the reason |

No help lines or tooltips: no +DB paragraph, no Hidden hint, no "not on the sheet" tooltips.

## What a player sees

Their own investigator only. No Luck: players roll Luck when the Keeper requests it; `LuckSection` is the Keeper's only. Opposed: [opposed-flyout.md](opposed-flyout.md). Assist: helping another character ([assist.md](assist.md), "What a player sees").

## Code

### `registerOtherFlyout()` (`index.js`, called from `main.js` at `ready`)
- **How it works:** Returns `false` unless `player/` `panelHere()`: the Keeper's client with `rollboxEnabled` on, or a player's with the Player Rollbox and their own switch on. Otherwise forgets the last tab used and the tab shown, installs one `updateActor` hook (an assist group changed: `assistGroupChanged`, then `playerAssistChanged` when the Keeper's tab wasn't drawn, [assist.md](assist.md)), and calls `registerFlyout("other", { title: "Other", render: renderOtherFlyout, columns: otherColumns })`. `index.js` also re-exports `registerAssistGroups` (`assist-group.js`), which `main.js` calls at `ready` on its own. The menu host offers the Other button for every selection ([panel.md](panel.md)); a player's menu shows it when one of its features is allowed (`playerMenu`).
- **Connects to:** `panel/` (`registerFlyout`); `player/index.js` (`panelHere`); Foundry's `Hooks.on("updateActor")`; `assist.js`, `player-assist.js`.
- **Could interact poorly with:** modules that update actors' flags often: each update is checked for `assistGroup` in its changed flags and ignored otherwise. **Assumed.**

### `renderOtherFlyout(body, { actors, everyone, start, setTitle, close, selectionChanged, cardChanged, allowed, pickTarget })` and `OtherFlyout` (`index.js`)
- **How it works:** `everyone` (from the menu host): nothing is selected and `actors` are every player's investigator. The menu host calls it when the flyout opens and again when the selection changes while it is open; each call builds a new `OtherFlyout` from scratch. Nothing selected, or a player with no tab allowed, draws nothing and returns nothing. Otherwise it returns a controller `{ apply(start) }` the menu host keeps while the flyout is open, so a later click on the character sheet's Luck reaches the open flyout instead of redrawing it. `allowed` and `pickTarget` default to the player Rollbox's `canUse` and `pickTarget`; a test may pass its own.
  - **Tabs** (`build`): the shared `tabBar` ([flyouts.md](flyouts.md)), one button per tab from `tabsFor(game.user, allowed)` with its id in `data-section`, `role="tab"` with `aria-selected`; a tab that can't be used for this selection is `disabled`. `usable`: only Item can be unusable, needing exactly one character and not `everyone`; every other tab is always usable (the Keeper's Assist says what it needs; a player's helpers and opponent are targeted).
  - **Which tab** (`pick`): the module-level `lastTab` if usable, else its fallback (`FALLBACK`: Item → Luck), else Item for one character or Luck for two or more or `everyone`, else the first usable tab. `lastTab` is set by a tab click and by a starting `section` (the sheet's Luck); a fallback shown never changes it, so the chosen tab comes back once it can be used. It lives until the page reloads (`registerOtherFlyout` clears it).
  - **`show(id, carry)`:** empties the tab's place and draws Item (`renderItem`, `item.js`), Luck (`LuckSection`, `luck.js`), Assist (`renderAssist`, `assist.js`) or Opposed (`renderOpposedRoll`, `flyouts/opposed/`), with the context `{ actors, close, selectionChanged: carry, cardChanged, targeting, pickTarget }` (`targeting` true for a player; `actors` empty with `everyone`, so Assist offers Add a character). Luck gets `{ everyone }`. `carry` is the menu host's `selectionChanged` on a redraw for a new selection, so Assist and Opposed keep their choices; a tab click draws them afresh. Then `setTitle` sets the flyout's title to the tab's, and `cardChanged()` lets the character cards follow (Assist's column).
  - **`apply({ section, plain, send })`:** a starting state, from a click on the character sheet: `section` becomes the last tab used and is shown if it isn't already (an open Luck tab keeps what the Keeper set); `plain` and `send` go to the Luck tab's `apply` (below).
- **Connects to:** `panel/` (the menu host's `context`: `actors`, `start`, `setTitle`, `close`, `selectionChanged`, `cardChanged`); `item.js`, `luck.js`, `assist.js`; `flyouts/opposed/` (`renderOpposedRoll`); `player/index.js` (`canUse`, `pickTarget`); `flyouts/flyout.js` (`tabBar`); `utils.js` (`element`, `warn`).
- **Could interact poorly with:** nothing outside Rollbox. The menu host keeps only Other's controller, so a sheet click reaches the Luck tab but never the Opposed tab inside a player's Other: a right click on a characteristic opens the Opposed flyout on its own (`openOpposed`, [panel.md](panel.md)), which for a player offers Target your opponent too. **Assumed.**

### `tabsFor(user, allowed)` (`index.js`)
- **How it works:** The Other flyout's tabs for this user, in order, each `{ id, label, title }`: for the Keeper (`user.isGM`) Item, Luck, Assist; for a player Opposed, Assist, each kept only when `allowed(feature)` (`canUse`, `player/index.js`) is true. A player never gets Luck or Item. A permission check that throws counts as not allowed (with a console warning).
- **Connects to:** `OtherFlyout`; `player/index.js`.
- **Could interact poorly with:** nothing. **Assumed.**

### `otherColumns(actors)` (`index.js`; registered as the flyout's `columns`)
- **How it works:** The character cards' value columns while Other is open: `assistColumns(actors)` (`assist.js`) while the Assist tab is shown, otherwise null, the cards' own SAN and Luck. Reads the module-level `shownTab`.
- **Connects to:** `MenuHost#columns` ([panel.md](panel.md)); `assist.js`.
- **Could interact poorly with:** nothing. **Assumed.**

### `LuckSection` (`luck.js`, exported)
- **How it works:** `new LuckSection(body, actors, { everyone })`, built from scratch with the tab, for one or more characters (every investigator with `everyone`). The Keeper's only: a player's Other flyout never has the Luck tab (`tabsFor`). State: difficulty, dice, Blind, label, Group Luck on or off, and the tie pick.
  - **Luck list** (`luckList`): each character's name (with the full name as its `title`) and Luck from skill-values' `attributes()`; a sheet without a Luck value (most creatures; CoC7 parses `system.attribs.lck.value` and warns "Roll threshold has not been set" when it isn't a number) reads "No Luck", greyed and italic (`rollbox-other-luck-none`). With `everyone`, the shared `whoLine`'s two short lines instead.
  - **Group Luck roll** (`groupOffered`, `drawGroupLine`, `targets`): Keeper Rulebook pp. 89-90, "the player whose investigator has the lowest Luck score … should make the roll". Offered with two or more selected characters (not with `everyone`) when at least one has a Luck value (`lowestLuck` from `skill-values/`). Ticked, the request goes only to the lowest-Luck character; on a tie, nothing is sent until the Keeper picks one (by `actorKey`). Characters without a Luck value are left out.
  - **How:** the shared Difficulty, Dice and Blind rows (`howRows`) and a Label box (`textInput`). `update()` redraws only what depends on them, so typing in the label keeps its focus.
  - **Sending** (`request`, `send`): `checkRequest({ checks: [{ kind: "attribute", name: "lck" }], difficulty, dice, blind, label })`, then `send(request, targets)`. The button's words are `sendLabel(targets, { everyone })`. `targets()` leaves out every character without Luck (not with `everyone`, which sends to every investigator); with no one left the buttons are greyed out with the red line "No Luck on this sheet." (`missing`), so a sheet click's Shift + Left sends nothing. The buttons are also greyed out while a tie isn't picked, and while a send runs (`runSend`). The result is `showResult` with "Luck check".
  - **`apply({ plain, send })`:** from a click on the character sheet's Luck: `plain` puts the options back to a Regular check with no dice, not blind and no label (a Shift click, as CoC7's sheet rolls it); `send` (true) then sends it.
- **What each request does** (player characters, NPCs): [roll-requests.md](roll-requests.md), "What happens for each request". A Luck check is CoC7's ordinary attribute check, so a player gets CoC7's own Luck roll link and an NPC is rolled for the Keeper.
- **Connects to:** `skill-values/` (`attributes`, `lowestLuck`); `roll-requests/` (`checkRequest`, `send`); `flyouts/flyout.js` (`button`, `howRows`, `runSend`, `sendLabel`, `sendSection`, `showResult`, `textInput`, `whoLine`); `utils.js` (`actorKey`, `element`).
- **Could interact poorly with:** nothing beyond `send()`'s own notes. CoC7 offers Luck spending on its own result card; Rollbox doesn't touch it. **Assumed.**

### `renderItem(body, actors)` (`item.js`, exported) and `ItemFlyout` (`item.js`)
- **How it works:** The Other flyout draws it in its Item tab when that tab is shown; each call builds a new `ItemFlyout` from scratch (nothing picked, options at their defaults). It draws only for exactly one character: the Other flyout greys the Item tab out otherwise (nothing selected included), and anything else draws nothing.
  - **Weapons** (`weaponsOf`): the actor's items with `type === "weapon"`, A–Z. Each weapon's rows come from `roll-requests/`' `weaponSkills(actor, weapon)`: its main and alternative skill when CoC7's `system.usesAlternativeSkill` is true (automatic, burst or thrown weapons) and the two skills differ, otherwise the one skill a request would use (`weaponSkill`: the alternative when the weapon uses one and it is set, else the main skill). Each row sends `weaponRequest({ weaponId, skill: "main" | "alternative" })`, so the skill shown is exactly the one requested. Values come from `skills(actor)` (`skill-values/`), found with skill-values' `findSkillRow`: by CoC ID first, then by name, the order roll-requests finds the sheet skill in, so the row shows the skill a request will send (a weapon's stored skill name can be a CoC ID such as `i.skill.throw`, as in CoC7's compendium weapons). A row with no skill (nothing set at all) is greyed out, because `send()` would skip it. An automatic, burst or thrown weapon with no alternative skill set shows its main skill (CoC7's `skillAlternative` fallback). A weapon whose skill can't be read gets one row and a console warning.
  - **Picking:** one radio group (named per flyout, so two drawn flyouts never share it) for the weapon rows and the improvised row. Each row's value is `<weapon id>#main` or `#alternative`.
  - **Improvised weapon:** "What is it?" is required. The skill choices, the "Other…" list and which skill a choice means are `flyouts/improvised.js`'s, shared with the Action flyout's Attack tab ([flyouts.md](flyouts.md)): Fighting (Brawl) by default, or Throw (`IMPROVISED_SKILLS`, with their CoC IDs), found in `skills(actor)` with `findSkillRow` so a sheet skill shows its own value and a missing one its base value (`improvisedSkill`); "Other…" is a list of every row of `skills(actor)` (trained first, then A–Z; `otherSkillList`), and nothing is sent until one is picked.
  - **Damage** (`damageBlock`): a `valueLine` (`shared/`, starting "0") whose rule is `tidyDice` then `damageText` from `roll-requests/`, with "0" meaning no damage; a `dicePicker` with `damageBonus: true` on that line, inside `customDice` ("Custom damage"). A line `damageText` refuses turns red and keeps the buttons disabled. `request()` passes "0" as no damage ("") and anything else as typed: `roll-requests/` fills in `DB` and `½DB` from the character's damage bonus when it sends. The section shows only for the improvised weapon.
  - **Quick-picks** (`quickFormula`): None and five dice under the line; a click writes "0" or "1D6+DB" into the line, which the Keeper can still change (typing, or Custom damage). The button matching the line shows pressed. The row is marked with `hideWhenSimplified` ([shared.md](shared.md)).
  - **Half DB for Throw** (`thrown`): when the improvised skill is Throw (skill-values' `sameSkill` with Throw's entry: by CoC ID `i.skill.throw`, or a skill named Throw picked in Other…), `update()` calls the picker's `halfBonus(true)` (toggle "+½DB", writes `½DB`), the quick-picks read "1D3+½DB" and so on, and a DB already on the line becomes ½DB (`withHalfBonus`). Thrown weapons add half the damage bonus in the rulebook's weapons table, as CoC7's own thrown weapons do (`CoC7Utilities.halfDB`). Switching back to Brawl gives the whole bonus again.
  - **Options:** the shared Difficulty, Dice and Blind rows (`howRows`, [flyouts.md](flyouts.md)); Blind's `on` goes into the request's `blind` option. `update()` redraws only what depends on them (pressed buttons, the improvised fields and damage, the status line and the send buttons), so typing keeps focus.
  - **Status line** (the shared `sendSection`'s `ready()`): while something required is missing (a weapon picked, the improvised one named and its skill picked, damage that is dice), the button is greyed out and the line says what, in red; once all is there it is hidden (no summary).
  - **No Label field:** the label is the weapon's or object's ("Firearms (Handgun) with the .38 Revolver", "Fighting (Brawl) with Candlestick", from `roll-requests/`).
- **Connects to:** `skill-values/` (`skills`, `findSkillRow`, `sameSkill`); `roll-requests/` (`weaponRequest`, `improvisedRequest`, `weaponSkills`, `damageText`, `send`); `flyouts/flyout.js` (`button`, `howRows`, `levelsNode`, `line`, `runSend`, `segmented`, `sendLabel`, `sendSection`, `showResult`); `flyouts/improvised.js` (`IMPROVISED`, `IMPROVISED_SKILLS`, `improvisedSkill`, `otherSkillList`); `shared/index.js` (`valueLine`, `valueBox`, `tidyDice`, `dicePicker`, `customDice`, `hideWhenSimplified`, `withHalfBonus`, `NO_DICE`); `utils.js` (`element`, `warn`); CoC7 weapon data `system.skill.main` / `alternativ` and `system.usesAlternativeSkill` (read by `weaponSkill`).
- **Could interact poorly with:**
  - CoC7's choice of a weapon's skill: `usesAlternativeSkill` is true for any weapon with the automatic, burst or thrown property. Such a weapon with two different skills gets two rows, so the Keeper picks (a single shot from a submachine gun: its main row). An alternative skill stored on a weapon without one of those properties is ignored, as CoC7's sheets hide it then (`weapon-header.hbs`). **Assumed** (from the CoC7 8.15 source).
  - Foundry's global `button`, `input` and `select` styles: every rule is scoped under `.rollbox-panel` and Foundry loads module styles into its `modules` cascade layer, after its own (BUILD-GUIDE "The panel and CSS"). **Assumed.**
  - An update to the character while the flyout is open (a weapon added, a skill improved) doesn't redraw it, so it shows the sheet as it was when drawn (the menu host's rule). The request itself reads the sheet when it is sent. **Assumed.**

### Sending from the Item tab (`ItemFlyout#request`, `#send`)
- **How it works:** `request()` is `weaponRequest({ weaponId, skill, difficulty, dice, blind })` for a weapon row (`skill` "main" or "alternative", from the row), or `improvisedRequest({ what, skill: { name, cocid }, damage, difficulty, dice, blind })`; null while the pick is incomplete: a Send then sends nothing and the status line says what is missing. The button is greyed out while a send runs (`runSend`, no double sends) and while the damage isn't dice. Its words are `sendLabel([actor])`: "Send to <name>", or "Roll for NPC" when the character has no player owner. A click → `send(request, [actor])`. The result under the button is `showResult` ([flyouts.md](flyouts.md)) with "Item check": "Item check sent to:" with "Alice (Player 1)", "Rolled for you:" with "Guard", or "Not sent:" with "Alice: …" and the reason. The flyout stays open with its choices, so the same request can be sent again.
- **What each request does** (player character, NPC, damage roll, missing skill): [roll-requests.md](roll-requests.md), "What happens for each request".
- **Connects to:** `roll-requests/index.js` `send()`.
- **Could interact poorly with:** nothing beyond `send()`'s own notes. **Assumed.**

### `other.css`
- **How it works:** Listed in `module.json` `styles` after `shared/shared.css`, which gives the buttons, rows of buttons, the weapon list and its rows (`rollbox-list`, `rollbox-row`), text boxes and the "Other…" drop-down, labelled lines, hints, sections, the damage line, the picker, the Blind toggle, the status line, the action buttons and the result line. This file keeps what only the Other flyout has: the tabs (like the Check flyout's, with 8px of space under the tab bar), the Luck list (muted, scrolling past about 140px; its rows 2px apart with 1px by 4px padding), the Group Luck line and its italic hint; and for the Item tab the greyed-out weapon row with no skill, the weapon's name and skill, the quick-picks' size, the improvised block and the chosen skill line; every rule scoped under `.rollbox-panel`. The weapon list scrolls past about 230px (`shared.css`). Its radios draw at 14px (`--checkbox-size`, set in `shared.css` for every list row): Foundry draws radios and tick boxes as Font Awesome glyphs in `::before` / `::after`, sized by that variable, not by the input's box, so a larger glyph would hang below the last row and make the list scroll. The six quick-picks use small type and no side padding so "1D10+½DB" fits. A weapon row with a disabled radio is drawn in the theme's disabled colour (`--rollbox-disabled`, readable rather than faded), found with `:has()` (supported by the Chromium in Foundry's desktop app).
- **Connects to:** `panel/panel.css`, `shared/shared.css`.
- **Could interact poorly with:** Foundry's radio and tick-box drawing: if a Foundry update stops using `--checkbox-size`, the glyphs could overflow (the list would scroll a little, nothing breaks). **Assumed.** Foundry's light interface theme: the flyout follows Rollbox's own Theme setting, not Foundry's. The "Other…" list's options are drawn by the operating system and may ignore the dark colours. **Assumed.**

## Hooks, overrides, keybindings
- Hooks: `updateActor`, installed by `registerOtherFlyout` (an assist group changed, so an open Assist is drawn again); otherwise the menu host calls `render`. A player's targeting is `player/targeting.js`'s (Foundry's own targeting).
- Class overrides: none.
- Keybindings: none.

## Settings
None of its own. Shown only while the Rollbox switch (`rollboxEnabled`) is on. A player's tabs follow the Player Rollbox settings through `canUse` (`rollboxPlayerOpposed`, `rollboxPlayerAssist`, in the Player Rollbox section's "What players can do" group; read by `player/index.js`, not here). `rollboxPlayerLuck` stays registered (hidden from Configure Settings) but gives a player nothing: they have no Luck tab.
