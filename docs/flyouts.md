# Flyouts (`scripts/flyouts/`)

Every flyout lives under `scripts/flyouts/`, one folder per flyout and one file per tab. This document covers what the folder holds and `flyout.js`, the DOM helpers and Send flow every flyout uses. Each flyout has its own document:

| Folder | Flyout | Document |
| --- | --- | --- |
| `action/` | Action: `index.js` (the flyout, its tabs, who acts), `target.js` (the target box), `weapons.js`, `attack.js`, `maneuver.js`, `spell.js` | [action-flyout.md](action-flyout.md) |
| `check/` | Check: `index.js` (the flyout and its tabs), `characteristic.js`, `skill.js`, `sanity.js` (the Sanity tab) | [check-flyout.md](check-flyout.md), [sanity-flyout.md](sanity-flyout.md) |
| `other/` | Other: `index.js` (the flyout and its tabs), `item.js`, `luck.js`, `assist.js`, `assist-split.js`, `assist-group.js` and `player-assist.js` (the Assist tab) | [other-flyout.md](other-flyout.md), [assist.md](assist.md) |
| `opposed/` | Opposed (the Keeper's Opposed button; a player's Other tab) | [opposed-flyout.md](opposed-flyout.md) |
| `alert/` | The flyout alert (being attacked or shot at) | [alert-flyout.md](alert-flyout.md) |
| `improvised.js` | The improvised weapon, shared by Other's Item tab and Action's Attack tab | below |

A flyout imports `flyout.js` as `../flyout.js`, and the other shared controls (value line, dice picker, status line) from `../../shared/index.js`. The alert builds its own buttons and imports nothing from `flyout.js`.

**Status key:** *Confirmed* only when the build guide's Internal API registry or changelog says so. Everything is **assumed** unless stated otherwise.

## Code

### `flyout.js`: `button`, `glyphButton`, `textInput`, `segmented`, `line`, `diceLine`, `tabBar`, `searchBox`, `howRows`, `sendLabel`, `whoLine`, `OWN_RESULT`, `noneSent`, `actorTag`, `runSend`, `sendSection`, `showResult`, `CHECK_TABS`, `filterRows`, `levels`, `levelParts`, `levelsNode`, `diceText`, `diceChoices`, `DIFFICULTY_LABELS`; private `DICE_LABEL`, `assignedPlayer`, `ownHow`, `resultArea`, `resultGroup`, `askedName`
- **How it works:** What every flyout needs, written once, built with `textContent` only, so a name typed by anyone never becomes HTML (`element` itself is in `utils.js`).
  - `button(className, text, onClick)` and `glyphButton(className, icon, onClick, { text, textClass, label, tooltip })`: shared's (`button.js`), re-exported here so every flyout takes them with the other helpers; always `type="button"`, so they never submit anything ([shared.md](shared.md)). `glyphButton` is the Font Awesome button: Check's clear button, Opposed's crosshair and ✕ buttons, Assist's target, ✕ and Add a character.
  - `textInput(className, placeholder, ariaLabel)`: a text box with a placeholder and an `aria-label`, no label of its own (placeholders only, [DESIGN.md, "Flyouts"](DESIGN.md#flyouts)). Used by the Sanity tab's cause fields, the Luck label, the Action flyout's target box and its improvised weapon.
  - `segmented({ choices, get, set, label })`: a row of buttons where one is pressed (`rollbox-segment`, `data-value`, `aria-pressed`; `label` names the group for screen readers). It returns `{ element, buttons, sync() }`; a click calls `set(value)` (the flyout then redraws what depends on it) and `sync()` marks the pressed one.
  - `line(label, …children)`: a labelled line ("Difficulty" then its row).
  - `tabBar(tabs, { className, tabClass, key, onPick, disabled })`: a flyout's tab bar, one `role="tab"` button per `{ id, label }` (`rollbox-btn rollbox-tab` plus `tabClass`), its id in `dataset[key]` (`tab`, or Other's `section`), greyed out when `disabled(id)` is true; a click calls `onPick(id)`. Returns `{ element, buttons, select(id) }`; `select` sets `aria-selected` on the open tab (the menu host's heading watches it, [panel.md](panel.md)). Used by the Check, Other and Action flyouts and each Opposed side, so their tabs are built one way.
  - `searchBox({ className, label, value, onInput })`: the skill search box (`type="search"`, placeholder "Search skills", `aria-label` from `label`), calling `onInput(text)` on each keystroke. Used by the Check flyout's Skill tab and each Opposed side ("Search Harvey's skills").
  - `howRows(state, onChange, { own })`: the Difficulty (Regular · Hard · Extreme · Hidden, `DIFFICULTY_LABELS`) and ± Dice (−2 … +2, p. 91, `diceLine`) rows with the tall Blind toggle beside them (shared's `blindToggle`, `blind-toggle.js`). Used by the Check flyout and the Other flyout's Item and Luck tabs. It reads and writes `state.difficulty`, `state.dice` and `state.blind` and returns `{ element, sync(), blind }`; the Check flyout turns `blind` off and disables it on a combined roll. With `own` (a player's own check: Make check) there are no rows at all: the element is an empty, hidden `rollbox-how` (`ownHow`), since the check is made at once, Regular with no dice (difficulty and dice are the Keeper's call, on the Keeper's requests; [DESIGN.md, "Flyouts"](DESIGN.md#flyouts)), and the flyout's layout code stays the same.
  - `sendLabel(actors, { everyone })`: the one send button's words ([DESIGN.md, "Flyouts"](DESIGN.md#flyouts)) in the Check flyout, its Sanity tab, and the Other flyout's Item, Luck and Assist tabs: "Send to all players" with `everyone` (nothing selected: every investigator); for one character it names who it goes to (the Keeper acting for anyone in the turn order): "Roll for <name>" for an NPC (roll-requests' `ownersOf` is empty: Rollbox rolls them for the Keeper), else "Send to <players> (<name>)": the player the character is assigned to (a non-GM user among `game.users` whose `character` is that actor, `assignedPlayer`, guarded), or with nobody assigned the player owners' user names joined with ", " ("Send to <name>" when they have none); who the request goes to doesn't change; for several, "Roll for NPCs" when none has a player owner, else "Send to each (N)". A character whose owners can't be read counts as a player character. Each is a private whisper with CoC7's roll link (or a private roll for an NPC): there is no Send to chat and no Copy link. A player's "Make check" and the Action flyout's buttons don't use it.
  - `whoLine(actors, { everyone, className })`: the line under a flyout's title naming who it is for: the names joined with ", " (the full text as its tooltip), or, with `everyone`, two short lines (`rollbox-everyone-note`): "No one selected: this goes to every investigator." and "Select tokens to choose who.". Used by the Check flyout, its Sanity tab (in place of the SAN list) and the Luck tab (in place of the Luck list).
  - `noneSent()`: a new send result with nothing sent (`{ requested: [], rolled: [], skipped: [], unavailable: false }`, the shape `roll-requests/` `send` returns), for a flyout that adds results up or skips the send (Opposed's `create`, Assist's `send`).
  - `actorTag(actor)`: what a flyout row's `data-actor` holds, the character's uuid, else its name, else `""` (Opposed's sides and rows, Assist's rows, Opposed's `picksKey`). Unlike utils' `actorKey` it never falls back to the id.
  - `OWN_RESULT`: `showResult`'s words for a player's own check: the heading "CoC7's check, in chat:" and the investigator's name, since CoC7 rolled it at once (or posted its combined card for them to roll).
  - `diceLine(...children)` (with the private `DICE_LABEL`): the bonus and penalty dice row, labelled "± Dice" with the hover text "Bonus (+) or penalty (−) dice", used by `howRows` and each Opposed side.
  - `runSend(menu, work, show)`: one Send. It does nothing while `menu.sending`; otherwise sets it, redraws (`menu.update()`, which greys the buttons out), awaits `work()`, catches and logs any error (`keepers-rollbox | a request failed.`), clears `sending`, calls `show(result)` (null when it threw) and redraws again.
  - `sendSection(buttons, { statusClass, status })`: the send section at the foot of every flyout: the status line, the flyout's buttons in a row (`rollbox-actions`) and the result area (`rollbox-result`, `aria-live`) under them, returned as `{ element, status, result, ready(missing, sending) }`. `ready()` greys every button out while something is missing (said in red with the status line's `missing()`) or a send runs, and hides the line otherwise (greyed out until complete, no summary). A button with a `data-keep` attribute is never greyed out (Cancel in Opposed, Assist and the Action tabs). `statusClass` is the line's own class (Opposed's tie line, which it writes with `note()` once nothing is missing); `status` is a status line the flyout shows elsewhere (Assist's, under its result), and the section then holds only the buttons and the result.
  - `showResult(area, result, { what, heading, name, notes })`: the result's layout: a heading and one name per line: "<what> sent to:" with each character and their players ("Alice (Test)"); "Rolled for you:" with each NPC; "Not sent:" with "Name: reason" (or the reason alone for a whole opposed card); then `notes`. `heading` and `name` replace the first heading and its lines (Opposed: "Opposed card made:", "Alice: Test rolls on the card"; a player's own check: `OWN_RESULT`). A thrown error "Something went wrong; see the console (F12)."; no CoC7 links "CoC7's roll links aren't available; nothing was sent."; nothing at all "Nothing was sent.". Classes: `rollbox-result-group`, `rollbox-result-heading`, `rollbox-result-line`.
  - `CHECK_TABS`: the two tabs (Characteristic, Skill) of the Check flyout and of each Opposed side; their rows are skill-values' `checkChoices()`. There is no Attribute tab: Luck is the Other flyout's, Sanity is the Check flyout's own tab, Idea and Know are INT and EDU checks with a label.
  - `filterRows(rows, text, divider)`: the skill search of the Check flyout and each Opposed side: hides each `{ node, name }` row whose name doesn't hold the text (skill-values' `comparable`: accents, case and extra spaces ignored), hides the divider while searching, and returns how many rows still show (the Check flyout offers "+ Add" at 0).
  - `levels(row)`: "60 · 30 · 12", or `NO_VALUE` ("—", `utils.js`) without a value; for text-only places (a Check tile without a value).
  - `levelParts(row)` / `levelsNode(className, row)`: the same values as spans (the value, its half and fifth, and the " · " between them in `.rollbox-level-sep`), so the page reads "55 · 27 · 11" in every theme while the Art Deco theme hides the separators and draws CoC7's "55 (27/11)" with CSS. Used by the Check list rows and the Skill tab's "+ Add" row, the Item tab's weapon rows and chosen skill, and the Action flyout's weapon rows and Maneuver's skill line.
  - `diceText(dice)`: "1 bonus die" / "2 penalty dice", "" with none. `diceChoices()`: the −2 … +2 choices for `segmented` (`MAX_DICE` from `roll-requests/`).
- **Connects to:** `utils.js` (`element`, `NO_VALUE`, `sameActor`, `warn`); Foundry's `game.users` (`assignedPlayer`); `skill-values/` (`comparable`); `roll-requests/index.js` (`ownersOf`, `DIFFICULTIES`, `MAX_DICE`); `panel/menu-host.js` (reads the tab bars' `aria-selected` for the heading); `shared/index.js` (`blindToggle`, `withBlind`, `statusLine`, `button`, `glyphButton`); every flyout folder but `alert/`; `shared/shared.css` (the classes it gives).
- **Could interact poorly with:** nothing (DOM and text only). **Confirmed** by the flyouts' tests only.

### `improvised.js`: `IMPROVISED`, `IMPROVISED_SKILLS`, `improvisedSkill`, `otherSkillList`
- **How it works:** The improvised weapon, written once for the Other flyout's Item tab and the Action flyout's Attack tab (both send it as an ordinary skill check labelled with the object, roll-requests `improvisedRequest`, since there is no CoC7 weapon for it). `IMPROVISED` (`"improvised"`) is the pick value of the "+ Improvised weapon" row. `IMPROVISED_SKILLS`: Brawl (Fighting (Brawl), `i.skill.fighting-brawl`, the default), Throw (`i.skill.throw`) and Other…. `improvisedSkill(choice, other, rows)`: the skill a choice means for a character: Brawl or Throw as the character's own row (skill-values `findSkillRow`), or the skill's name and CoC7 id with no value when it isn't on the sheet (the request then uses its base value); Other… the picked row of the "Other…" list, or null while none is picked; an unknown choice counts as Brawl. `otherSkillList(rows, { className, value, onChange })`: the "Other…" `<select>` (`aria-label` "Other skill", first option "Pick a skill…"), one option per skill row with its value ("—" without one), each option's value the row's index.
- **Connects to:** `other/item.js`, `action/attack.js`; `skill-values/` (`findSkillRow`); `utils.js` (`element`, `NO_VALUE`).
- **Could interact poorly with:** nothing (DOM and text only). **Confirmed** by the Item and Attack tests only.
