# Roll requests (`scripts/roll-requests/`)

The only code that talks to CoC7 about rolls. The flyouts describe what they want as plain data (`checkRequest`, `sanityRequest`, `weaponRequest`, `improvisedRequest`, `opposedRequest`); `send()` turns that into CoC7's own request links, whispered to each character's player owners. There is no public request and no copied link (a CoC7 link isn't tied to a character, so an open link anyone can roll has no use here). Characters with no player owner (NPCs) are rolled at once on the Keeper's side, privately, through CoC7's actor methods, whoever started the request: a player's request relayed through the Keeper's client rolls its NPC there too, on the active Keeper's client (never a CoC7 link whispered to the Keepers, which names no character, so a Keeper's click would roll the selected tokens); only an opposed card a player started leaves its Start rolls for the Keeper to press. A player's own check (`makeCheck`, `own-rolls.js`) is made on their own client by CoC7's own actor check, fast-forwarded past its roll dialog as a Shift + click on its sheet is, never as a request to themselves. Attacks, reloads and spells go to CoC7's own methods (`attack.js`), and CoC7 makes its own attack card. CoC7 rolls, compares, spends Luck, pushes and applies every result; Rollbox writes no dice or success-level code. On a player's client (Player Rollbox on) a request for their own characters goes out from their client; anything CoC7 needs a GM for goes to the Keeper's client through Rollbox's socket (`relay.js`). With the Player Rollbox off `send()` does nothing on a player's client. Every CoC7 call is guarded, so a CoC7 change makes a request do nothing (with a warning) instead of throwing. Rollbox never changes how CoC7 handles a click on a link: a Keeper who clicks a request's link with tokens selected rolls it for each selected token, as CoC7 does.

## What happens for each request

| Request | Player character (has a player owner) | NPC (no player owner) |
| --- | --- | --- |
| Check: characteristic, Luck, a plain SAN roll | `@coc7.check` link in a message | `actor.characteristicCheck` / `attributeCheck(key, true, {difficulty, poolModifier, blind: true})` |
| Check: skill on the sheet | link, by the sheet skill's own CoC ID, else its name | `actor.skillCheck(skillItemUuid, true, …)` |
| Check: skill missing from the sheet | link (by Rollbox's CoC ID, else the name), after checking CoC7 can find the skill; CoC7 adds it when rolled | `actor.runRoll({rollType: "R/MA", threshold: base value, …})` and a note to the Keeper naming it; nothing added |
| Idea / Know | an INT / EDU check; the Keeper types "Idea" or "Know" as the label | the INT / EDU check as above |
| Combined check | `combinedall` / `combinedany` link; CoC7's combined card | one private `R/MA` roll at the highest value (Any one) or lowest (All of them), with a note naming the checks |
| Weapon | skill check labelled "Skill with the Weapon" | the skill check as above, and a note to the Keeper naming the weapon |
| Improvised weapon | skill check labelled "Skill with What", plus a damage roll in the message | the skill check, and a note to the Keeper naming the object, with the damage roll |
| Any check with the Keeper's label | the link shows the check, then the label: "Hard Spot Hidden · notice the knife" | the check as above, and a note to the Keeper: "Guard: Hard Spot Hidden · notice the knife" |
| Sanity | `@coc7.sanloss` link | CoC7's Sanity card made on the Keeper's side; Rollbox clicks its Sanity roll; the card is public |
| Opposed | one CoC7 opposed card with both sides; Rollbox clicks Start rolls (only when the Keeper sent it) | the same card (Start rolls rolls the NPC side; when a player started it, the Keeper presses Start rolls) |
| Any request a player started (relayed) | as above | rolled privately at once on the active Keeper's client, as above (an opposed card's Start rolls left for the Keeper) |
| Attack (Action flyout) | CoC7's own attack card (`actor.weaponCheck`), on the attacker's client; Rollbox sets the card's Keeper-only toggles from the Keeper's client | the same; the card waits for its Roll button |
| Maneuver (Action flyout) | Rollbox's notice, from the attacker's client; once the target answers, CoC7's opposed card in combat mode made on the Keeper's client, Start Rolls pressed; the player rolls their own row | the same; Start Rolls rolls the NPC's side, whoever started the maneuver |

A player's own check from their own panel (Make check) is none of these: `makeCheck` has CoC7 make it on their client (below).

## Code

### `requests.js`: `checkRequest({ checks, all, difficulty, dice, blind, label })`
- **How it works:** Checks and tidies one check, or a combined check when two or more are given. Each check is `{ kind, name }`: `characteristic` with CoC7's key (`str` … `edu`, case ignored); `attribute` with `lck` (Luck) or `san` (a plain SAN roll, as a Shift-click on SAN on CoC7's sheet rolls it; a Sanity check with a loss goes through `sanityRequest`); `idea` and `know` give null, since Idea and Know are INT and EDU checks with a label; `skill` with the name as listed, optional `cocid`, and optional `value` (the Check flyout's "+ Add" entry's group base or the Keeper's typed value, used for an NPC that lacks the skill). `difficulty` is `regular` (default), `hard`, `extreme` or `hidden`; anything else is regular. `dice` is whole bonus (+) or penalty (−) dice, clamped to ±2 (Keeper Rulebook p. 91). `blind` is forced off on a combined check (CoC7's combined card is always public, Gap 5). `label` is cleaned (`cleanLabel`). There is no Pushed option: a `pushed` field is ignored (pushing happens from CoC7's result card, Gap 3). Returns `{ type: "check", checks, combined, all, difficulty, dice, blind, label }`, or `null` with one `console.warn` when any check is unknown or none is given.
- **Connects to:** `CHARACTERISTICS` from `skill-values/`. Called by the Check flyout and its Sanity tab's plain SAN roll ([check-flyout.md](check-flyout.md), [sanity-flyout.md](sanity-flyout.md)), Luck and Assist in the Other flyout ([other-flyout.md](other-flyout.md), [assist.md](assist.md)), the Spell tab's first-casting POW ([action-flyout.md](action-flyout.md)) and combat's Roll to notice ([combat.md](combat.md)).
- **Could interact poorly with:** nothing outside the module (pure data).

### `requests.js`: `sanityLoss(text, empty)`
- **How it works:** The one rule for a Sanity loss, used by `sanityRequest` and the Sanity tab's value lines, so the two always agree. Spaces removed and upper-cased ("1d4 + 1" → "1D4+1"); empty gives `empty` (`null` when the field is required). A loss is a whole number or dice (`D6`, `1D6`, `2D10`; no zero dice or faces) joined by `+` or `-`, at most 20 characters; anything else gives `null`. CoC7 hands both losses to Foundry's `Roll` and draws the failure loss's maximum every time the card renders, so a malformed loss would break the card (DEVELOPING.md "Cards" › "Sanity").
- **Connects to:** `sanityRequest`; `flyouts/check/sanity.js` ([sanity-flyout.md](sanity-flyout.md)).
- **Could interact poorly with:** nothing (pure text).

### `requests.js`: `sanityRequest({ success, failure, cause, creature })`
- **How it works:** `success` / `failure` are the SAN lost on a success / failure, checked and tidied by `sanityLoss` (empty is `"0"`); one that isn't a loss gives `null` with a warning. `cause` becomes the link's label as given (shown to players instead of the numbers); the Sanity tab passes "Sanity check · Seeing a ghoul" or its default "Sanity (1/1D6)" ([sanity-flyout.md](sanity-flyout.md)). `creature` goes to CoC7's `sanReason`, with characters that break link options removed (`cleanOption`). No blind (CoC7 can't, Gap 4), no difficulty, no dice.
- **Connects to:** the Check flyout's Sanity tab.
- **Could interact poorly with:** CoC7's creature record (`maxLossToSanReason`): the same creature typed two ways counts as two sources. **Assumed.**

### `requests.js`: `weaponRequest({ weaponId, skill, difficulty, dice, blind })`
- **How it works:** Records the weapon's item id, which skill (`skill`: `"main"` or `"alternative"`; anything else is `null`: the skill CoC7's cards would use) and the options. At `send()` the weapon is looked up on each character's sheet and its skill chosen by `weaponSkill(actor, weapon, skill)`. Sent as an ordinary skill check labelled "Firearms (Handgun) with the .38 Revolver" or "Throw with the Knife"; never `@coc7.item`, which starts CoC7's attack card and ignores difficulty, dice and blind (Gap 2; attacks go through `startAttack` instead). A weapon not on the sheet, or with no skill, skips that character with a notice.
- **Connects to:** the Other flyout's Item tab ([other-flyout.md](other-flyout.md)); CoC7 weapon data `system.skill.main` / `alternativ` / `usesAlternativeSkill`.
- **Could interact poorly with:** weapons whose skill id points at a deleted skill: the stored name is used, so the skill may be requested as missing. **Assumed.** Weapon data: **Confirmed** for `system.skill.main`; the alternative skill **Assumed**.

### `resolve.js`: `weaponSkill(actor, weapon, which)` and `weaponSkills(actor, weapon)` (`weaponSkills` public)
- **How it works:** A weapon stores `system.skill.main` and `system.skill.alternativ` (CoC7's spelling), each `{ id, name }`; a stored skill is the sheet skill with that id, else the stored name (which can be a CoC ID). `weaponSkill` with `which` `"main"` or `"alternative"` takes that one; without it, the alternative when `system.usesAlternativeSkill` is true (automatic, burst or thrown), else the main skill, as CoC7's opposed and combined cards choose. An alternative that isn't set falls back to the main skill, like CoC7's `skillAlternative` getter (`models/item/weapon-system.js`), so an automatic or thrown weapon with only a main skill still has one. Returns `{ kind: "skill", name, cocid, value: null }`, or null when nothing is set. `weaponSkills` gives the rows a flyout lists: `[{ which: "main", skill }, { which: "alternative", skill }]` when the weapon uses an alternative skill and it differs from the main one (skill-values' `sameSkill`: by CoC ID and name, with Rollbox's table linking a name to its CoC ID, so "Throw" and "i.skill.throw" are one skill), otherwise one entry with the skill a request would use. An alternative stored on a weapon without the automatic, burst or thrown property is ignored, as CoC7's own weapon sheet hides it then (`templates/items/weapon-header.hbs`).
- **Connects to:** `weaponRequest` (via `planCheck`), `flyouts/other/item.js`, `flyouts/action/weapons.js`.
- **Could interact poorly with:** CoC7 changing its weapon data or the getter's fallback. **Assumed** (from the CoC7 8.15 source).

### `requests.js`: `improvisedRequest({ what, skill, damage, difficulty, dice, blind })`
- **How it works:** `skill` is a name or a skill check object. Sent as a skill check labelled "Fighting (Brawl) with Candlestick". When `damage` is given, the character's damage bonus (`system.attribs.db.value`: CoC7 stores `-2`, `-1`, `0`, `1D4`, `2D6` …) replaces `DB`, and half of it replaces `½DB` or `1/2DB` (halved the way CoC7's `CoC7Utilities.halfDB` does: dice sizes and positive numbers round down, negative numbers away from zero). Any "+0" or "-0" term is then left out (`withoutZeros`), so a zero damage bonus, half of a damage bonus of 1, or a typed "1D6+0" reads "1D6". The result must hold only dice and arithmetic and pass Foundry's `Roll.validate`; then it goes in the same message as a Foundry inline roll, `[[/r 1D6+1D4 # Candlestick damage]]`, which the player clicks. Otherwise the request goes without damage: `planCheck` returns a `warning`, and `sendTo` tells the Keeper (the planning step only reads the actor). For an NPC the damage roll is in the Keeper's note. Nothing is added to the sheet.
- **`damageText(text)`** (`resolve.js`, public): the same check on the formula as the Keeper writes it, before a damage bonus is known (`DB` counted as 0), returning the formula without spaces or null. The Item tab and the Action flyout's improvised weapon use it for their damage line, so the flyout and the request follow one rule.
- **Connects to:** the Other flyout's Item tab ([other-flyout.md](other-flyout.md)) and the Action flyout's improvised weapon ([action-flyout.md](action-flyout.md)); Foundry's inline rolls (`TextEditor._enrichInlineRolls`, deferred `/r` roll).
- **Could interact poorly with:** a damage bonus set to text CoC7 doesn't compute (e.g. `auto` before CoC7 has worked it out): the damage is left out with a notice. Modules that restyle inline rolls. **Assumed.** `Roll.validate`, the inline damage roll and `db.value` (a bonus of 0): **Confirmed**.

### `requests.js`: `opposedRequest({ sides })`
- **How it works:** Exactly two sides, each `{ actor, check, dice }`, with two different characters (`actorKey`: by uuid, else id or name); otherwise `null` with a warning. Dice clamped to ±2. A side may be `{ actor, open: true }` (a player's Opposed: the opponent's check is the Keeper's): it keeps its character, has no check and no dice, and is marked `open`; at least one side must have a check. Every side carries `open` (false when filled). No difficulty: the other side's result is the difficulty (p. 92); can't be pushed (p. 90).
- **Connects to:** the Opposed roll ([opposed-flyout.md](opposed-flyout.md)); the Action flyout's Maneuver and Opposed POW ([action-flyout.md](action-flyout.md)).
- **Could interact poorly with:** nothing (pure data).

### `index.js`: `send(request, actors, { involved, byPlayer, keeperRolls, quiet })`; private `sendTo`
- **How it works:**
  1. On a player's client: nothing with the Player Rollbox off. With it on, a request that needs a GM (`needsKeeper`: an opposed card always; any character this player doesn't play, i.e. an NPC or another player's character) goes to the Keeper's client (`sendThroughKeeper`, below); the rest goes on here as on the Keeper's. Then nothing (one `console.warn`, `unavailable: true`) unless the system is CoC7 and `CONFIG.CoC7Link.documentClass` is registered.
  - `involved` (a player's client only): characters taking part without being sent anything (Assist's helpers); their uuids go with a relayed request so the Keeper's client accepts a check when the player's character only helps (`mayRelay`, below).
  - `keeperRolls` (Keeper's client only; combat's weapon-drawn Roll to notice and About to attack's): each character is rolled privately for the Keeper at once, whoever owns them, as an NPC is (`rollForKeeper` with `owned` when the character has a player owner). Never a request whispered to the Keepers: CoC7's link names no character, so a Keeper's click on it would roll for the selected tokens (`CoC7Link._onLinkClick`). `quiet`: an NPC rolled for the Keeper gets no note line before CoC7's card (`rollForKeeper(plan, actor, { quiet })`), since the weapon-drawn list shows each result itself.
  - `byPlayer` (set by the Keeper's relay, `sendForPlayer`, and honoured only on a Keeper's client): a player started the request, so an opposed card's Start rolls isn't pressed (`sendOpposed`). Its NPCs are still rolled for the Keeper (step 4).
  2. Every request is whispered: the flyouts' one send button ("Send to all players", "Send to <name>", "Send to each (N)", "Roll for NPC(s)") has no other mode, and there is no `mode` option.
  3. Opposed requests go to `sendOpposed` (below). Otherwise each actor is handled once (`uniqueActors`: duplicates and tokens without an actor dropped).
  4. Per character (`sendTo`): `ownersOf(actor)`. Unreadable: skipped with a warning. Non-empty: a request whispered to the players. Empty: an NPC, rolled for the Keeper, also when a player started it (the relay runs on the active Keeper's client only). Never a CoC7 link whispered to the Keepers: the link names no character, so a Keeper's click would roll the selected tokens ([DESIGN.md, "Sending and who rolls"](DESIGN.md#sending-and-who-rolls)).
  5. A failure for one character is caught, warned and recorded; the others still go.
- **Returns:** `{ requested, rolled, skipped: [{ actor, reason }], unavailable }` for the flyouts to show. `actor` is null for an opposed card that couldn't be made at all, or a player's request the Keeper's client didn't send (`askKeeper`'s reason: "no Keeper online", "the Keeper can't be reached", "the Keeper's Rollbox didn't answer"; or "the Keeper's Rollbox couldn't send it" when it refused).
- **Connects to:** `ChatMessage.create`; CoC7's actor methods and link handler; `player/` `playerRollboxOn`. Every Keeper's flyout, a player's Opposed, Assist and Action, and combat's Roll to notice send through it.
- **Could interact poorly with:**
  - Foundry: a message with an empty `whisper` list is public, so Rollbox never creates one: a player character whose owners have no ids is skipped. **Assumed** (Foundry behaviour, DEVELOPING.md "CoC7 links and options" › "Whispers").
  - CoC7's roll dialog lets the player change difficulty, dice and card type when clicking a request (Gap 9, accepted). **Assumed.**
  - A player who owns several characters picks one in CoC7's actor picker; the link isn't tied to the character. **Assumed.**
  - Chat-log modules that rewrite message content before render. **Assumed.**

### A player's own check: `makeCheck(request, actor)` (`index.js`), `makeOwnCheck(plan, actor)` (`own-rolls.js`)
- **How it works:** Make check on a player's panel ([check-flyout.md](check-flyout.md)) calls `makeCheck` with a `checkRequest` (one check or a combined check) and the player's own investigator. Not a request and no whisper to themselves. Anything but a check, or no actor: nothing. Without CoC7's links: `unavailable: true`. The check is planned as for a request (`planCheck`); a plan error, or a missing skill CoC7 can't find (`skillsCoC7CantFind`: CoC7 would do nothing), is skipped with the reason. Then `makeOwnCheck` has CoC7 make the check on this client, exactly as a click on the value on CoC7's own sheet does:
  - **One check:** CoC7's actor method through `callActor` with `fastForward` **true** (Make check rolls straight into chat), so CoC7 skips its "select modifier" window, as a Shift + click on its sheet does (`CoC7RollNormalize.trigger`: `fastForward` sets `isShiftKey`, which skips `createRoll`'s `CoC7RollDialog`), rolls and posts its card in the table's roll mode (`characteristicCheck(key, true, { difficulty, poolModifier })`, `attributeCheck` for Luck, `skillCheck` by the sheet skill's uuid, else its key). The player's flyouts send Regular with no dice (they have no Difficulty or Dice rows); a player's Assist roll sends the difficulty the Keeper set. CoC7 posts an unrolled "standby" card only from a GM's client, so on a player's client the check is rolled.
  - **Combined:** CoC7's combined card through its link handler (`linkActorClick`, `_onLinkActorClick(actor, { check: "check", subtype: "combinedall" | "combinedany", rolls })`, the roll strings joined with `&&`), which waits for the player's roll on the card. A key that can't go in a roll string is refused ("a name can't go on CoC7's combined card"); no handler: "CoC7's combined card can't be reached".
  - **Not awaited:** `makeOwnCheck` asks CoC7 and returns at once, so the flyout never waits on CoC7's roll or card (one check is fast-forwarded with no window; a combined card waits for the player's roll on it); a failure is logged (`callActor`'s warning, or "CoC7 couldn't make <name>'s combined card.").
- **Returns:** `send()`'s result shape; `requested` holds the investigator once CoC7 was asked, `skipped` the reason otherwise.
- **Connects to:** `resolve.js` (`planCheck`), `links.js` (`rollString`, `difficultyLevel`, `isSafeRollKey`), `coc7.js` (`callActor`, `linkActorClick`, `skillsCoC7CantFind`, `coc7LinksReady`); private `oneCheck` (`own-rolls.js`, which picks the actor method); CoC7 `actor.characteristicCheck`, `attributeCheck`, `skillCheck` and `CoC7Link._onLinkActorClick` (internal).
- **Could interact poorly with:** CoC7 changing what its actor checks do with `fastForward` true (no window, then the card): the player's check would open the window again or not roll. **Confirmed** in e2e (CoC7 8.15, Foundry v14 build 370). The combined card from a player's client: CoC7's link handler asks the Keeper's client through CoC7's own socket, so it needs a GM online. **Assumed.** CoC7 renaming `_onLinkActorClick`: no combined card, with the reason in the flyout. **Assumed.** A combined check has no window either (CoC7's combined card waits for the player's roll on it). **Assumed.**

### Player characters: `requestFromPlayers`, `postRequest` (`index.js`), `requestText` (`coc7.js`), `resolveCheck`, `planCheck`, `linkForPlan` (`resolve.js`)
- **How it works:** First, for any skill missing from the sheet, `skillsCoC7CantFind` (below); if CoC7 can't find it, the character is skipped and the Keeper told, because CoC7 would do nothing when the player clicked. Then the link (`linkForPlan`); a name that can't go in a link (holds `, : [ ] { } # & < >`) skips the character with a notice. The message is CoC7's own wording, `CoC7.MessageTargetCheckRequested` ("Your keeper has requested {name} make a {check} roll."), with the actor's name escaped, or the same sentence in English if the key is gone. Speaker alias: the sending user's name, as CoC7's Create link tool does. Whispered to the owners' ids, one message per character. An improvised weapon's damage roll follows on a new line. The message carries no Rollbox flag.
- **A skill given as a CoC ID** (a weapon's stored skill can be `i.skill.throw`, as on CoC7's compendium weapons): `resolveSkill` treats the name as the CoC ID, so the label reads the skill's name from Rollbox's table ("Throw with the Knife"), or the sheet skill's name, never "i.skill.throw". A CoC ID the table doesn't have is shown as its words ("i.skill.made-up-skill" → "Made Up Skill") and has no base value for an NPC.
- **Skill keys:** on the sheet, the sheet item's own CoC ID, else its sheet name. A sheet skill's name alone isn't always enough: CoC7's `getItemByName` compares only the part in brackets ("Handgun"), and a renamed own language ("Language (English)") matches "Language (Own)" only by CoC ID. A table CoC ID on a sheet skill that lacks one would make CoC7 add a duplicate, so it is never used for on-sheet skills. Missing: Rollbox's table CoC ID (CoC7 finds it in its compendium), else the name. The sheet skill is found by skill-values' `sheetSkill` (by CoC ID; the own-language flag only when Language (Own) is asked for by its CoC ID; then by name), the table entry by `tableSkill`, and an open-ended skill's base by `groupBase`.
- **Labels:** with the Keeper's label (`keeperLabel`, the label is cleaned again there with `cleanLabel`), the check as CoC7 names it goes in front, joined by " · ", so the player still sees what to roll: "Hard Spot Hidden · notice the knife" (Hard and Extreme are named; Regular and Hidden add nothing), "INT · Idea", and for a combined check the names joined by " + ": "Spot Hidden + Listen · notice the knife". The names are this character's (a renamed own language reads "Language (English)"). ### `links.js`: `checkLink`, `combinedLink`, `sanityLink`, `rollString`, `damageRoll`, `cleanLabel`, `cleanOption`, `wholeDice`, `isSafeOption`, `isSafeRollKey`, `difficultyLevel`, `DIFFICULTIES`, `MAX_DICE` (the last two re-exported by `index.js`)
- **How it works:** Pure text.
  - Difficulty is always a number in links and actor calls: Regular 1, Hard 2, Extreme 3, Hidden −1 (`CoC7DicePool.difficultyLevel`; with Hidden the Keeper sets the difficulty on CoC7's result card afterwards). Not `+` / `++`: the Sanity card reads its difficulty with `parseInt` and throws on them (`CoC7DicePool#difficulty` setter). In combined and opposed roll strings difficulty is one digit and **0 means hidden** (`parseRolls`).
  - Every check link carries `difficulty` and `blind` or `blind:false` (CoC7 reads the string `"false"` as false, `actor.skillCheck`), never left to the roller's chat mode (DEVELOPING.md "CoC7 links and options" › "v14 chat modes"). Dice go through `wholeDice` (whole dice, at most `MAX_DICE` either way, anything else none; `requests.js` normalises with the same function) in `checkLink` and `rollString`, so a link never carries more than two. `poolModifier` only when there are bonus or penalty dice: CoC7 picks the link's text by whether the option is there, so `poolModifier:0` would read "[hard] Spot Hidden check(0)"; a missing one rolls as 0 (`CoC7RollNormalize`, `options.poolModifier ?? 0`).
  - Combined links carry `blind:false`; Sanity links `difficulty:1,poolModifier:0,blind:false` (CoC7 ignores `blind` there). `sanityLink` takes the Sanity request itself (`success`, `failure`, `creature`, `label`), for the players' message, and cleans the creature again with `cleanOption`. The Sanity link keeps `poolModifier:0`: `CoC7SanCheckCard.create` sets the difficulty only when `poolModifier` is defined.
  - Labels (`cleanLabel`): `[ ] { } < >` removed, spaces collapsed, HTML-escaped. The entities it writes (`&amp; &lt; &gt; &quot; &#39;`) are read back first, so cleaning cleaned text changes nothing; every link cleans its label again where it is written (`labelPart`), whatever the caller passed. Foundry decodes the message's entities before CoC7's enricher reads the label and puts it into the page as HTML (`<span>${name}</span>`), so angle brackets must be gone, not just escaped; brackets would start other enrichers.
  - Option values must pass `isSafeOption` (no `, : [ ] { } < >`); roll keys `isSafeRollKey` (also no `#` `&`). Angle brackets because CoC7's enricher puts a skill's name into the page as HTML and players can rename their own skills. Names that don't are refused, not altered, so CoC7 never gets a different skill's name. Free text for an option (a creature's name) goes through `cleanOption`.
  - `damageRoll(formula, flavor)`: `[[/r formula # flavor]]`, flavor cleaned and escaped.
- **Connects to:** CoC7's enricher (`CoC7Link._createLink`) and click handler (`_onLinkActorClick`); `escapeHtml` from `utils.js`. `DIFFICULTIES` and `MAX_DICE` are read by `flyouts/flyout.js` and `attack.js`.
- **Could interact poorly with:** CoC7 changing its link syntax: links show as plain text. Link text and options: **Confirmed** for a whispered `@coc7.check` skill request with difficulty, a combined link and a Sanity link; the rest **Assumed**.

### `maneuver.js`: `postManeuverNotice`, `readManeuverNotice`, `noticeText`, `maneuverRolls`, `counterWeapons`, `answerManeuver`, `maneuverForPlayer`, `rollOwnSide`, `onOpposedRender`, `restoreManeuvers`, `MANEUVER_OFF_FLAG`; private `makeManeuverCard`, `NOTICE_FLAG`, `ANSWERS`, `advantaged`, `ADVANTAGED_KEPT`, `trustedAuthor`, `itemKey`, `dodgeKey`, `weaponSide`, `noteOnNotice`, `watchCard`, `setManeuver`, `sheetsInPlay`, `answerNotice`, `noticeOfCard`, `unopposedManeuver`, `GOAL_WORDS`
- **How it works:** CoC7 8.15 runs a maneuver on its opposed card in combat mode (`CoC7ChatOpposedMessage`, `isCombat`), reading a win as "<name> maneuver was successful." only from a weapon with Maneuver on (`isManeuver`, from a roll of type `item`); by hand three people act (the attacker right-clicks a skill, the defender joins, the Keeper sets the sides and presses Start Rolls). Rollbox drives the same card. **The notice:** `postManeuverNotice({ actor, weapon, target, goal })` posts a public chat message spoken by the attacker (`ChatMessage.getSpeaker({ actor })`), `<div class="rollbox-maneuver-notice"><p>Cecil attempts to push away (maneuver) Deep One Hybrid.</p></div>` (`noticeText`; "break free from" for Break free), with `flags.keepers-rollbox.maneuver` (`NOTICE_FLAG`) `{ attacker, target, weapon, goal, answer: null, defence: null, card: null }` (uuids, the weapon's item id; `defence` the target's weapon for Fight back or Counter, noted with the answer). `readManeuverNotice` reads it back (null for anything else; `answer` only one of `ANSWERS`, "dodge" · "fight" · "counter" · "none"). Anyone can write a chat message with that flag, so a notice is read only when its author (`ChatMessage#author`) is a GM or a player of its attacker (`trustedAuthor`: a player's own Attempt is posted from their client); a notice naming someone else's attacker (an NPC) is ignored everywhere: no alert, no card. **The rolls:** `maneuverRolls({ attacker, weapon, target, answer, defence })`: the attacker's side `<uuid>#item#<weapon>#<Build dice>#1`, the weapon one of their `maneuverWeapons` with its skill set, the dice `maneuverDice(attacker's Build, target's Build)` (impossible: refused); the defender's side for **Dodge** `<uuid>#skill#<the skill CoC7 marks isDodge, else Dodge>#1`, for **Fight back** the chosen weapon (one of `meleeWeapons(target)`) as `item#<weapon>`, a Maneuver-on weapon too (its Maneuver is switched off while CoC7 makes the card, below), or as its fighting skill (`skill#<name>`) when CoC7 can't find its skill or a Maneuver-on weapon's switch couldn't be made (`fightAsSkill`: CoC7 would call the win a maneuver), for **Counter** the weapon picked (`defence`, one of their maneuver weapons; else the first of `counterWeapons(target)`: their maneuver weapons with the unarmed weapon first) with their own Build dice (`maneuverDice(target's Build, attacker's Build)`). A weapon goes by its name when that is unique on the sheet and safe in a roll string, else its uuid (CoC7's `getItemOrAdd` takes both; Roll damage finds a winner's weapon by name). `rollString` writes each (`#1`, Regular, always). ### The Keeper relay: `relay.js` (`askKeeper`, `registerRelay`, `onKeeperRequest`; private `socket`, `keeperOnline`, `senderOf`, `onMessage`, `CHANNEL`, `REPLY_TIMEOUT_MS`, `NO_KEEPER`), `index.js` (`registerKeeperRelay`, `registerHelperCheck`; private `needsKeeper`, `sendThroughKeeper`, `sendForPlayer`, `packRequest`, `unpackRequest`, `packResult`, `unpackResult`, `mayRelay`)
- **How it works:** Foundry's own module socket: `"socket": true` in `module.json` gives the channel `module.keepers-rollbox` (`game.socket.emit` / `game.socket.on`). `registerKeeperRelay()` at `ready` listens on the Keeper's client always and on a player's with the Player Rollbox on (`false` otherwise, or without a socket); on a Keeper's client it also hooks `onOpposedRender`, and on the active Keeper's runs `restoreManeuvers`. With no GM online (`keeperOnline()` false) the player is told "Rollbox: the Keeper needs to be online for this." and nothing is sent; with no answer within `REPLY_TIMEOUT_MS` (20 s) the request is skipped.
  - **"send"** (`sendThroughKeeper` → `sendForPlayer`): the request (an opposed request's characters as uuids), and the actors' uuids. The Keeper's client rebuilds the request with the same normaliser the player's flyout used (`unpackRequest`: `checkRequest`, `sanityRequest`, `weaponRequest`, `improvisedRequest`, or `opposedRequest` with the sides' characters found again by utils' `actorFromUuid`), so a request typed by hand in the browser console is cleaned again or refused; an unknown type gives null. `mayRelay` then decides whether the sender may ask for it (`playsFor`, CoC7's `actor.owners`): an opposed roll when one of its two sides is theirs (with a side left open, the filled side must be theirs); anything else when every requested character is theirs, or, for a check only, when one of the characters taking part without a roll is theirs (`involvedUuids`: Assist's helpers, so a player's character can help while an NPC or another player's character rolls). That helper list comes from the player's socket message, so it is trusted only when every roller has no player owner (an NPC), or when the Assist part confirms it (`registerHelperCheck`, below): each roller stands in an Assist group holding every listed helper and the sending player's own investigator. A forged list naming another player's investigator as the roller is refused. A refusal is one warning. Otherwise it runs its own `send()` with `byPlayer: true` (whispers to owners, CoC7's opposed card; an NPC rolled privately for the Keeper at once, and an opposed card's Start rolls left to them). The answer is `send()`'s result as uuids; the player's client turns it back into characters for the flyout's result lines.
  - **"aboutToAttack"** (combat's `about-to-attack.js` `aboutToAttackForPlayer`): a player's attack out of combat waits for the Keeper's About to attack decision; `askKeeper`'s `timeout` option (default 20 s) is ten minutes for it, since the Keeper answers by hand.
  - **"ticks"** (`keeperTicks`, no answer): a player's attack asks the Keeper's client to set CoC7's Keeper-only toggles on that player's attack card (above).
  - **"maneuver"** (`maneuverForPlayer`, `maneuver.js`): a player's answer to a maneuver on their character; the Keeper's client makes CoC7's opposed card (above).
  - **Other parts' message types** (`onKeeperRequest(type, handler)`): on a Keeper's client another part adds a type the Keeper's client answers; the handler gets the payload and the sending user (Foundry's sender id) and checks itself that the player may ask for it. Returns `false` on a player's client or for a handler that isn't a function. `registerRelay` keeps types added this way, so the order of the two at `ready` doesn't matter. Used for **"notice"**: combat's weapon-drawn notice, which only the Keeper's client makes, so the player who drew never sees it (a whisper always shows to its author) (`combat/notice-cards.js` `noticeForPlayer`, [combat.md](combat.md)).
  - **`registerHelperCheck(check)`** (`index.js`): the Assist part registers `helpersInGroup` here at `ready` on the Keeper's client ([assist.md](assist.md)), so this part checks a relayed check's helpers against the Assist groups without importing a flyout. Without one registered, a relayed check with helpers for another player's character is refused; a check whose throws is refused with one warning.
- **Connects to:** Foundry's `game.socket`, `game.users.activeGM`, `game.users.get`, `fromUuidSync` (through utils' `actorFromUuid`); `player/index.js` (`playerRollboxOn`); `main.js` (`registerKeeperRelay` at `ready`); `combat/notice-cards.js` (`onKeeperRequest("notice", …)`); `flyouts/other/assist-group.js` (`registerHelperCheck`).
- **Could interact poorly with:** a server that adds no sender id: every relayed message is ignored, so a player's requests that need the Keeper time out. **Assumed** (Foundry v14 adds it). Other modules on the same channel: none can use it (it is named after the module id). **Seen in e2e** (a player's opposed roll, Assist with an NPC roller and attack-card toggles went through the Keeper's client).

## Settings
`rollboxAutoRollNpc` (`attack.js`, Gameplay rules section's Rolling group, *Keeper setting, applies to everyone.*, world, Boolean, default on, no reload): **Roll NPC attacks at once**. `rollboxAutoRollAttacks` (`attack.js`, Gameplay rules section's Rolling group, *Keeper setting, applies to everyone.*, world, Boolean, default on, no reload): **Roll investigators' attacks at once** (the Keeper's own attacks for an investigator). `rollboxRollMyAttacks` (`attack.js`, Player Rollbox section's Each player's own group, *Personal setting, affects only your screen.*, user, Boolean, default on, no reload): **Roll my attacks at once**, a player's own attacks through their Rollbox (`autoRolls` reads it on a player's client, `rollboxAutoRollAttacks` on the Keeper's). The sections only grey these out while their feature is off; the settings act whatever Gameplay rules or the Player Rollbox switch say. Also reads CoC7's world setting `worldEra` (read only, to predict CoC7's skill lookup) and the Player Rollbox switch (`player/` `playerRollboxOn`).
