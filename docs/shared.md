# Shared controls (`scripts/shared/`)

Controls and styles more than one menu uses, so each menu doesn't build its own. The editable value line, the compact dice picker and its Custom button, the Blind toggle, the status line, the menu helpers (buttons, rows of buttons, the check tabs and their search, the Difficulty / Dice / Blind rows, the main button's words, the Send runner and the result lines), and the shared stylesheet. They build text and DOM only: CoC7 and Foundry roll what the menus send. No hooks and no `register…()` function: the menus create them when they draw. One personal setting, Simplified dice UI, hides the Custom buttons and pickers and the menus' preset rows. Files: `menu.js`, `value-line.js`, `dice-picker.js`, `blind-toggle.js`, `status-line.js`, `shared.css`, `settings.js`.

**Status key:** *Confirmed* only when the build guide's Internal API registry or changelog says so. Nothing in this part has been tried at the table yet, so everything is **assumed** unless stated otherwise.

## What the Keeper sees

| Control | What it shows |
| --- | --- |
| Value line | a large line of plain text in a shaded box ("0 / 1D6", "1D6+DB"), with no box, border or outline around the text itself: click it and type. Enter or clicking away confirms: empty becomes 0, and a value the menu accepts is written back tidied ("1d6" → "1D6"). Text the menu refuses turns red and blocks Send |
| Custom button | full width ("Custom success or failure loss", "Custom damage"); a click opens its picker(s) under it, a second click closes them. Gone with Simplified dice UI on, as are the Sanity presets and the Item damage quick-picks |
| Compact dice picker | a small caption ("On a success"); number of dice as − n + and one row of dice D3 D4 D6 D8 D10 D12 D20 D100; "+ flat" − n +, "+DB" (damage only; "+½DB" while the menu asks for half, for a thrown object) and None on the right. It edits the value line above; typing in the line moves it |
| Blind toggle | a tall button with "Blind" written sideways, to the right of the Difficulty and Dice rows and spanning both. Click on (highlighted), click off. Greyed out when the menu can't send blind |
| Status line | just above the buttons, only in red when something is missing ("Type what the improvised weapon is"), while the send buttons are greyed out; otherwise hidden (Void, 2026-11-14: no "Sends …" summary). The Opposed view's tie line uses it, not in red |
| Result | under the buttons after a Send: a heading and one name per line: "Sanity check sent to:" (or "posted in chat for:") with each player's character (and their players), "Rolled for you:" with each NPC, "Not sent:" with "Name: short reason"; then the menu's note ("Click Apply on CoC7's card to take the loss.", "Assist card posted.") |
| Action buttons | the main one ("Request from player", "Send to each (N)", "Roll for NPC(s)", "Create opposed card") filled with the accent colour, the others beside it |

Picker clicks: a die with no number of dice makes it one die; "+" from no dice picks a D6; "−" to no dice leaves only the flat bonus; the flat bonus goes from 0 to 99 (a negative one can still be typed); None clears everything to 0. When the line holds something the picker can't show (1D6+1D4, or text that isn't dice), nothing shows pressed and the next click starts from nothing.

**Simplified dice UI** (setting): the Custom buttons and their pickers are gone, and the Keeper types into the value lines. The preset rows (Sanity presets, damage quick-picks) are gone too (Void's table check, 2026-11-14), so a menu shows only its typed value line. Where damage takes a bonus, `DB`, `½DB` and `1/2DB` are accepted ("1d6 + 1/2db" is read as 1D6+½DB). Changing it switches an open menu at once; the lines keep what they hold.

## Code

### `index.js`
- **How it works:** The part's public surface: it re-exports what other parts use from `menu.js`, `status-line.js`, `value-line.js` and `dice-picker.js` (the Blind toggle comes with `howRows`). Every menu imports `shared/` through it, never the files beside it (BUILD-GUIDE "Project layout"). `settings.js` is imported by the module's `settings.js` directly, as every part's settings file is.
- **Connects to:** every menu.
- **Could interact poorly with:** nothing. **Confirmed** by tests only.

### `menu.js`: `button`, `textInput`, `segmented`, `line`, `howRows`, `requestLabel`, `runSend`, `sendSection`, `showResult`, `CHECK_TABS`, `filterRows`, `levels`, `diceText`, `diceChoices`, `DIFFICULTY_LABELS`
- **How it works:** What every menu needs, written once. `button(className, text, onClick)` (always `type="button"`) builds with `textContent` only (`element` itself is in `utils.js`). `textInput` is a text box with a placeholder and `aria-label` (placeholders only, DESIGN "How every menu is laid out"). `segmented({ choices, get, set, label })` is a row of buttons where one is pressed (`rollbox-segment`, `data-value`, `aria-pressed`; `label` names the group for screen readers): it returns `{ element, buttons, sync() }`; a click calls `set(value)` (the menu then redraws) and `sync()` marks the pressed one. `line(label, …children)` is a labelled line ("Difficulty" then its row).
  - `howRows(state, onChange)`: the Check and Item menus' Difficulty and Dice rows (−2 … +2, p. 91) with the Blind toggle beside them. It reads and writes `state.difficulty`, `state.dice`, `state.blind` and returns `{ element, sync(), blind }`; the Check menu turns `blind` off and disables it on a combined roll.
  - `requestLabel(actors)`: the main send button's words in the Check, Sanity and Item menus: "Roll for NPC" (one) or "Roll for NPCs" (several) when every character has no player owner (roll-requests' `ownersOf` is empty: Rollbox rolls them for the Keeper; Void, 2026-11-14); otherwise "Request from player", or "Send to each (N)" for several. A character whose owners can't be read counts as a player character. Assist's "Send to rollers" doesn't use it.
  - `runSend(menu, work, show)`: one Send. It does nothing while `menu.sending`; otherwise sets it, redraws (`menu.update()`, which greys the buttons out), awaits `work()` (the menu's `send()` call, plus Assist's card), catches and logs any error (`keepers-rollbox | a request failed.`), clears `sending`, calls `show(result)` (null when it threw) and redraws again.
  - `sendSection(buttons, { statusClass, status })`: the send section at the foot of every menu: the status line, the menu's buttons in a row (`rollbox-actions`) and the result area (`rollbox-result`, `aria-live`) under them, returned as `{ element, status, result, ready(missing, sending) }`. `ready()` greys every button out while something is missing (said in red with the status line's `missing()`) or a send runs, and hides the line otherwise (Void, 2026-11-14: greyed out until complete, no summary). A button with a `data-keep` attribute is never greyed out (the Opposed view's and Assist's Cancel). `statusClass` is the line's own class (the Opposed view's tie line, which it writes with `note()` once nothing is missing); `status` is a status line the menu shows elsewhere (Assist's, under its result), and the section then holds only the buttons and the result.
  - `showResult(area, result, { what, mode, heading, name, notes })`: the result in Void's layout (2026-11-14): a heading and one name per line: "<what> sent to:" (whisper; each character with their players, "Alice (Test)") or "<what> posted in chat for:" (chat); "Rolled for you:" with each NPC; "Not sent:" with "Name: reason" (or the reason alone for a whole opposed card); then `notes`. `heading` and `name` replace the first heading and its lines (the Opposed view: "Opposed card made:", "Alice: Test rolls on the card"). Link mode shows "Link copied." or "Nothing was copied."; a thrown error "Something went wrong; see the console (F12)."; no CoC7 links "CoC7's roll links aren't available; nothing was sent."; nothing at all "Nothing was sent.". Classes: `rollbox-result-group`, `rollbox-result-heading`, `rollbox-result-line`.
  - `CHECK_TABS`: the three tabs (Characteristic, Attribute, Skill) of the Check menu and each Opposed side; their rows are skill-values' `checkChoices()`. `filterRows(rows, text, divider)`: both menus' skill search: hides each `{ node, name }` row whose name doesn't hold the text (skill-values' `comparable`: accents, case and extra spaces ignored), hides the divider while searching, and returns how many rows still show (the Check menu offers "+ Add" at 0).
  - `levels(row)` is "60 · 30 · 12", or `NO_VALUE` ("—", `utils.js`) with no value. `diceText(dice)` is "1 bonus die" / "2 penalty dice"; `diceChoices()` the −2 … +2 choices (`MAX_DICE` from `roll-requests/`).
- **Connects to:** `utils.js` (`element`, `NO_VALUE`, `warn`); `skill-values/` (`comparable`); `roll-requests/index.js` (`ownersOf`, `DIFFICULTIES`, `MAX_DICE`); `blind-toggle.js`; `status-line.js` (`sendSection`); every menu (`check-menu/`, `sanity-menu/`, `item-menu/`, `opposed-roll/`, `assist/`), through `index.js`; `dice-picker.js` (`button`); `shared.css`.
- **Could interact poorly with:** nothing (DOM and text only). **Confirmed** by the menus' tests only.

### `valueLine({ label, value, empty, check, onChange })`, `captioned(line, caption)`, `valueBox(parts)`, `tidyDice(text)` (`value-line.js`)
- **How it works:** `valueLine` builds an `<input type="text" class="rollbox-value">` with `aria-label` and returns `{ element, text, value, set(text) }`. `text` is what it shows; `value` is `check(text || empty)`: an empty line counts as `empty` ("0") while typing, so a cleared line never blocks Send. `input` marks it (`rollbox-value-invalid`, `aria-invalid`, and `size` from the text length) and calls `onChange`. Enter (`keydown`, default prevented, then `blur()`) and `blur` confirm: empty is written as `empty`; an accepted value is written back as `check` returned it; refused text stays as typed, red. `set()` shows a preset or the picker's formula without calling `onChange` (the caller redraws). `captioned` puts a small caption under a line ("success"); `valueBox` puts lines or captioned parts side by side in the shaded box, with "/" between them. `tidyDice` is the menus' tidy-up for typed dice: no spaces, upper case, `1/2DB` written `½DB`.
- **Connects to:** `sanity-menu/` (two lines, `check` = `sanityLoss` from `roll-requests/`, the same rule the request uses), `item-menu/` (damage, `check` = `tidyDice` then `damageText` from `roll-requests/`, "0" for no damage), `assist/` (what it's up against, a whole number).
- **Could interact poorly with:** Foundry's global `input` styles (border, background, focus outline): `shared.css` resets them under `.rollbox-panel`. The width uses CSS `field-sizing: content` (Chromium 123+, which Foundry v14's Electron has) with `size` as a fallback. **Assumed.** If Chromium fires `blur` when a focused line is removed (the menu redrawn after a selection change), `onChange` runs on the old menu, which is harmless. **Assumed.**

### `dicePicker({ label, line, damageBonus, onChange })` (`dice-picker.js`)
- **How it works:** Builds the compact picker for one value line and returns `{ element, sync(), halfBonus(on) }`. Every click reads the line (`diceParts`), changes one part, writes `diceFormula(...)` into the line with `line.set()`, redraws itself and calls `onChange()`. `sync()` shows what the line holds now: the menus call it from their `update()`, so typing in the line, a preset or a quick-pick moves the picker. `halfBonus(true)` makes the toggle read "+½DB" and write `½DB` (the Item menu calls it for Throw); it doesn't call `onChange`. The steppers' − and + have `aria-label`s ("On a success: number of dice: more").
- **Connects to:** `value-line.js` (the line it edits); `sanity-menu/`, `item-menu/`.
- **Could interact poorly with:** a narrow flyout: the dice row holds the stepper and eight dice in 10px type. Fits at 320px (checked in a headless Chromium harness with the module's CSS); at a larger Panel size the whole panel scales, so it still fits. **Assumed** until Void's look check.

### `diceParts(text, { damageBonus })`, `diceFormula(parts, { half })`, `withHalfBonus(text, half)` and `NO_DICE` (`dice-picker.js`; `withHalfBonus` and `NO_DICE` exported)
- **How it works:** `diceParts` reads a formula into `{ fits, count, die, bonus, db }`: `[1–9]D<die>`, an optional signed bonus (up to 99), an optional `+DB` or `+½DB` (only with `damageBonus`), or a plain number; "0" or empty is nothing; anything else has `fits: false`. The dice are matched longest first, so "1D100" is D100, not D10 and a 0; "1D45" isn't 1D4 and 5. `diceFormula` writes the formula text the requests take ("2D4+1", "1D6+DB", "1D4+½DB", "3", "DB"); nothing at all is `NO_DICE` ("0"). `withHalfBonus` rewrites a damage bonus whole or half ("1D6+DB" ↔ "1D6+½DB"); text the picker can't show is left alone. The Item menu uses it when the skill changes to or from Throw.
- **Connects to:** `dicePicker`, `item-menu/`.
- **Could interact poorly with:** nothing (pure text). **Confirmed** by tests only.

### `customDice({ label, pickers })` (`dice-picker.js`)
- **How it works:** A wrapper (`rollbox-dice-custom`) with a full-width toggle button (`aria-expanded`) and a panel holding the pickers, closed at first. Opening syncs the pickers. Returns `{ element, button, open, sync() }`. Hidden while Simplified dice UI is on, through `hideWhenSimplified` (below).
- **Connects to:** `sanity-menu/` (one button, two pickers), `item-menu/` (one button, one picker with +DB).
- **Could interact poorly with:** nothing known. **Assumed.**

### `simplifiedDice()`, `setSimplifiedDice(on)` and `hideWhenSimplified(node)` (`dice-picker.js`; the last two exported)
- **How it works:** `simplifiedDice()` reads `rollboxSimplifiedDice` through `getSetting` inside `try` (off if it can't be read, e.g. in a test without it). `hideWhenSimplified` marks an element with `rollbox-simplified-hides` and sets its `hidden` attribute from the setting; the Custom sections and the menus' preset rows (Sanity presets, Item quick-picks) use it. `setSimplifiedDice` is the setting's `onChange`: it sets `hidden` on every `.rollbox-simplified-hides` in the document, so an open Sanity or Item menu changes at once, without a reload. The value lines keep what they hold. `shared.css`'s `.rollbox-panel [hidden][hidden]` rule keeps it hidden whatever `display` a menu's own rule gives it.
- **Connects to:** `shared/settings.js`; `sanity-menu/`, `item-menu/`; Foundry calls `onChange` on the client whose value changed (`client/helpers/client-settings.mjs`).
- **Could interact poorly with:** nothing known. **Assumed.**

### `blindToggle({ onChange })` and `withBlind(rows, toggle)` (`blind-toggle.js`, used by `howRows`)
- **How it works:** `blindToggle` is a `<button class="rollbox-btn rollbox-blind">` reading "Blind", with `aria-pressed`; a click flips it and calls `onChange(on)` (nothing while disabled). Returns `{ element, on, disabled }`; the menu can set `on` and `disabled` (the Check menu turns Blind off and disables it on a combined roll) without `onChange`. `withBlind` lays the rows out in a column (`rollbox-how-rows`) with the toggle beside them (`rollbox-how`), stretched to their height. The text is turned sideways with CSS (`writing-mode: vertical-rl` and a 180° turn, so it reads bottom to top).
- **Connects to:** `check-menu/`, `item-menu/`; they read `on` into the request's `blind` option.
- **Could interact poorly with:** Foundry's global `button` styles: reset under `.rollbox-panel`. **Assumed.**

### `statusLine(className)` (`status-line.js`)
- **How it works:** A `<p class="rollbox-status …">` with `aria-live="polite"` and three methods: `missing(text)` (red: `rollbox-status-missing`), `note(text)` (plain) and `clear()`. Empty, it is hidden. Text only.
- **Connects to:** `sendSection` (`menu.js`), which makes every menu's line and calls `missing()` while its send buttons are greyed out and `clear()` once they work (Void, 2026-11-14: no summary of what will be sent); Assist makes its own and passes it in. The Opposed view's tie line is `note()` (worked-out information, like Assist's result block).
- **Could interact poorly with:** nothing. **Assumed.**

### `shared.css`
- **How it works:** Listed right after `mini-sheet.css` and before every menu's own file in `module.json` `styles`, so it is the base and a menu's own rule of the same weight wins. Every rule is scoped under `.rollbox-panel` and uses the panel's palette variables (`mini-sheet.css`, `docs/mini-sheet.md`), so the Theme, Panel colour, transparency and size apply. It holds:
  - one rule that keeps anything `[hidden]` hidden (`.rollbox-panel [hidden][hidden]`, which outweighs any one-class rule, so neither the menus nor the panel need `[hidden]` lists);
  - **the theme's colours on Foundry's own controls:** Foundry colours placeholders and tick boxes from its interface theme, not the panel's, so every `input`, `select` and `textarea` in the panel sets Foundry's `--input-placeholder-color` to `--rollbox-placeholder` (and `::placeholder` takes it too), and every tick box and radio sets `--checkbox-background-color` to `--rollbox-box` and `--checkbox-disabled-color` to `--rollbox-disabled`; under the Light theme a checked one takes the accent (`--checkbox-checked-color`) instead of Foundry's orange (build 368 `foundry2.css`);
  - sections (`rollbox-section`: a column, 12px of space before each, no lines or headings), the muted line under a menu's title (`rollbox-menu-who`), the status line (red `--rollbox-bad` when something is missing), the action row with the highlighted main button (`rollbox-primary`: the accent mixed 45% into the panel's solid colour, 1.6 times as wide as the others) and the icon button (`rollbox-icon-action`);
  - the result (`rollbox-result`: a heading and indented lines per group, `rollbox-result-heading`, `rollbox-result-line`); the Difficulty and Dice buttons beside the Blind toggle narrowed so "Extreme" fits (`.rollbox-how .rollbox-segment`);
  - the generic pieces every menu uses: buttons (`rollbox-btn`, also on the dice picker's buttons and steppers, the Custom button and the Blind toggle, which keep only their own size and place; the pressed look `--rollbox-pressed` with an accent border for `rollbox-tab[aria-selected]`, `rollbox-segment[aria-pressed]`, `rollbox-dice-button[aria-pressed]`, `rollbox-dice-toggle[aria-expanded]` and `rollbox-blind[aria-pressed]`; disabled in the theme's `--rollbox-disabled` text colour, not faded, so it stays readable), rows of buttons (`rollbox-segmented`), labelled lines (`rollbox-line`, `rollbox-line-label`), text boxes and drop-downs (`rollbox-input`), hints (`rollbox-hint`), lists with tick boxes or radios (`rollbox-list`, whose rows never shrink, and `rollbox-row`, whose inputs set Foundry's `--checkbox-size` to 14px so the glyph, 20px otherwise, doesn't hang below the row) and the trained/untrained divider (`rollbox-divider`);
  - the value line and its box, the Custom button and picker (their sizes; the look is `rollbox-btn`'s), and the Blind toggle (26px wide, the text turned sideways).
- **Connects to:** `mini-sheet/mini-sheet.css` (variables); every menu's CSS; Foundry's `--input-placeholder-color` and `--checkbox-*` variables.
- **Could interact poorly with:** Foundry's `modules` cascade layer and global styles (BUILD-GUIDE "The panel and CSS"). Another module's CSS that styles `[hidden]` elements under the panel. A Foundry update that renames its placeholder or tick-box variables: those would take Foundry's colours again. **Assumed** until Void's look check.

### `DICE_SETTINGS` (`settings.js`)
- **What it is:** the Simplified dice UI setting as plain data; `settings.js` at the top puts it second in the "Keeper's Rollbox" section, after the panel's switch, so it dims while the panel is off.
- **Connects to:** `setSimplifiedDice` (its `onChange`), `utils.js` (`PERSONAL`).
- **Could interact poorly with:** nothing known. **Assumed.**

## Hooks, overrides, keybindings
- Hooks: none.
- Class overrides: none.
- Keybindings: none. Enter in a value line confirms it; it sends nothing.

## Settings
- `rollboxSimplifiedDice` ("Simplified dice UI"; hint "Type dice into the Sanity loss and the improvised damage (e.g. 1D6+2, or 1D6+DB for damage) instead of opening the dice picker. The preset buttons are hidden too."; user scope, Boolean, default off; Personal note; `requiresReload: false`, applied at once through `onChange`). The key is permanent once released.
- `rollboxDiceEntry`: an earlier "Dice entry" setting, no longer registered. A value saved before 0.1 stays in Foundry's settings but is never read.
