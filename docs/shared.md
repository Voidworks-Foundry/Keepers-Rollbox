# Shared controls (`scripts/shared/`)

Controls and styles more than one flyout uses, so each flyout doesn't build its own, and the rules more than one part reads, so each is stated once. The editable value line, the compact dice picker and its Custom button, the Blind toggle, the status line, the button builder, the shared rules (`rules.js`), the one distance between two tokens (`distance.js`), how a firearm reloads (`reload-kind.js`), the right click that targets a character wherever Rollbox shows one (`target-click.js`) and the shared stylesheet. The flyout helpers (rows of buttons, the tab bar and the search box, the Difficulty / Dice / Blind rows, the one send button's words, the Send runner and the result lines) are in `scripts/flyouts/flyout.js` ([flyouts.md](flyouts.md)). They build text and DOM only: CoC7 and Foundry roll what the flyouts send. No hooks and no `register…()` function: the flyouts create them when they draw. One personal setting, Simplified dice UI, hides the Custom buttons and pickers and the flyouts' preset rows. Files: `index.js`, `value-line.js`, `dice-picker.js`, `blind-toggle.js`, `status-line.js`, `button.js`, `rules.js`, `distance.js`, `reload-kind.js`, `target-click.js`, `shared.css`, `settings.js`.

User guide: the value line and dice picker appear in [Check](../guide/check.md) (the Sanity tab) and [Other](../guide/other.md) (Item damage, Assist); Simplified dice UI is on the [Settings](../guide/settings.md) page.

**Status key:** *Confirmed* only when the [Internal API registry](DEVELOPING.md#internal-api-registry) says so or the maintainer checked it at the table, as marked; everything else is **assumed**.

## What the Keeper sees

| Control | What it shows |
| --- | --- |
| Value line | a large line of plain text in a shaded box ("0 / 1D6", "1D6+DB"), with no box, border or outline around the text itself: click it and type. Enter or clicking away confirms: empty becomes 0, and a value the flyout accepts is written back tidied ("1d6" → "1D6"). Text the flyout refuses turns red and blocks Send |
| Custom button | full width ("Custom success or failure loss", "Custom damage"); a click opens its picker(s) under it, a second click closes them. Gone with Simplified dice UI on, as are the Sanity tab's presets and the Item damage quick-picks |
| Compact dice picker | a small caption ("On a success"); number of dice as − n + and one row of dice D3 D4 D6 D8 D10 D12 D20 D100; "+ flat" − n +, "+DB" (damage only; "+½DB" while the flyout asks for half, for a thrown object) and None on the right. It edits the value line above; typing in the line moves it |
| Blind toggle | a tall button with "Blind" written sideways, to the right of the Difficulty and Dice rows and spanning both. Click on (highlighted), click off. Greyed out when the flyout can't send blind |
| Status line | just above the buttons, only in red when something is missing ("Type what the improvised weapon is"), while the send buttons are greyed out; otherwise hidden (no "Sends …" summary). The Opposed view's tie line uses it, not in red |
| Result | under the buttons after a Send: a heading and one name per line: "Sanity check sent to:" with each player's character (and their players), "Rolled for you:" with each NPC, "Not sent:" with "Name: short reason"; then the flyout's note ("Click Apply on CoC7's card to take the loss.", "Assist card posted.") |
| Action buttons | the one send button ("Send to all players", "Send to <name>", "Send to each (N)", "Roll for NPC(s)"; Opposed's "Create opposed card"; a player's "Make check", "Make opposed card", "Roll Hard STR" in Assist) filled with the accent colour, with Cancel beside it where a flyout has one. There is no Send to chat and no Copy link |

Picker clicks: a die with no number of dice makes it one die; "+" from no dice picks a D6; "−" to no dice leaves only the flat bonus; the flat bonus goes from 0 to 99 (a negative one can still be typed); None clears everything to 0. When the line holds something the picker can't show (1D6+1D4, or text that isn't dice), nothing shows pressed and the next click starts from nothing.

**Simplified dice UI** (setting): the Custom buttons and their pickers are gone, and the Keeper types into the value lines. The preset rows (Sanity presets, damage quick-picks) are gone too, so a flyout shows only its typed value line. Where damage takes a bonus, `DB`, `½DB` and `1/2DB` are accepted ("1d6 + 1/2db" is read as 1D6+½DB). Changing it switches an open flyout at once; the lines keep what they hold.

## Code

### `index.js`
- **How it works:** The part's public surface: it re-exports what other parts use from `settings.js` (`DICE_SETTINGS`), `status-line.js`, `button.js` (`button`, `glyphButton`), `blind-toggle.js` (`blindToggle`, `withBlind`, for `flyouts/flyout.js`'s `howRows`), `rules.js` (all but `metresPerUnit`, which only `distance.js` reads), `distance.js`, `reload-kind.js`, `value-line.js`, `dice-picker.js` and `target-click.js`. Every other part imports `shared/` through it, never the files beside it, `flyouts/flyout.js` included ([DEVELOPING.md, "Project layout"](DEVELOPING.md#project-layout)). Inside `shared/`, `dice-picker.js` imports `button.js` beside it, so `shared/` imports nothing from `flyouts/`. The module's `settings.js` reads `DICE_SETTINGS` through `index.js` too.
- **Connects to:** every flyout (`flyouts/flyout.js`: `blindToggle`, `withBlind`, `statusLine`, `button`, `glyphButton`); the module's `settings.js` (`DICE_SETTINGS`); combat (`rules.js`, `distance.js`, `target-click.js`), the panel's sheet and cards (`target-click.js`), the setup check (`reload-kind.js`), roll-requests' maneuver card (`rules.js`).
- **Could interact poorly with:** nothing. **Confirmed** by tests only.

### `valueLine({ label, value, empty, check, onChange })`, `captioned(line, caption)`, `valueBox(parts)`, `tidyDice(text)` (`value-line.js`)
- **How it works:** `valueLine` builds an `<input type="text" class="rollbox-value">` with `aria-label` and returns `{ element, text, value, set(text) }`. `text` is what it shows; `value` is `check(text || empty)`: an empty line counts as `empty` ("0") while typing, so a cleared line never blocks Send. `input` marks it (`rollbox-value-invalid`, `aria-invalid`, and `size` from the text length) and calls `onChange`. Enter (`keydown`, default prevented, then `blur()`) and `blur` confirm: empty is written as `empty`; an accepted value is written back as `check` returned it; refused text stays as typed, red. `set()` shows a preset or the picker's formula without calling `onChange` (the caller redraws). `captioned` puts a small caption under a line ("success"); `valueBox` puts lines or captioned parts side by side in the shaded box, with "/" between them. `tidyDice` is the flyouts' tidy-up for typed dice: no spaces, upper case, `1/2DB` written `½DB`.
- **Connects to:** `flyouts/check/sanity.js` (Check's Sanity tab: two lines, `check` = `sanityLoss` from `roll-requests/`, the same rule the request uses), `flyouts/other/item.js` (damage, `check` = `tidyDice` then `damageText` from `roll-requests/`, "0" for no damage), `flyouts/other/assist.js` (what it's up against, a whole number).
- **Could interact poorly with:** Foundry's global `input` styles (border, background, focus outline): `shared.css` resets them under `.rollbox-panel`. The width uses CSS `field-sizing: content` (Chromium 123+, which Foundry v14's Electron has) with `size` as a fallback. **Assumed.** If Chromium fires `blur` when a focused line is removed (the flyout redrawn after a selection change), `onChange` runs on the old menu, which is harmless. **Assumed.**

### `dicePicker({ label, line, damageBonus, onChange })` (`dice-picker.js`)
- **How it works:** Builds the compact picker for one value line and returns `{ element, sync(), halfBonus(on) }`. Every click reads the line (`diceParts`), changes one part, writes `diceFormula(...)` into the line with `line.set()`, redraws itself and calls `onChange()`. `sync()` shows what the line holds now: the flyouts call it from their `update()`, so typing in the line, a preset or a quick-pick moves the picker. `halfBonus(true)` makes the toggle read "+½DB" and write `½DB` (the Item flyout calls it for Throw); it doesn't call `onChange`. The steppers' − and + have `aria-label`s ("On a success: number of dice: more").
- **Connects to:** `value-line.js` (the line it edits); `flyouts/check/sanity.js`, `flyouts/other/item.js`.
- **Could interact poorly with:** a narrow flyout: the dice row holds the stepper and eight dice in 10px type. Fits at 320px (checked in a headless Chromium harness with the module's CSS); at a larger Panel size the whole panel scales, so it still fits. **Assumed** until a look check.

### `diceParts(text, { damageBonus })`, `diceFormula(parts, { half })`, `withHalfBonus(text, half)` and `NO_DICE` (`dice-picker.js`; `withHalfBonus` and `NO_DICE` exported)
- **How it works:** `diceParts` reads a formula into `{ fits, count, die, bonus, db }`: `[1–9]D<die>`, an optional signed bonus (up to 99), an optional `+DB` or `+½DB` (only with `damageBonus`), or a plain number; "0" or empty is nothing; anything else has `fits: false`. The dice are matched longest first, so "1D100" is D100, not D10 and a 0; "1D45" isn't 1D4 and 5. `diceFormula` writes the formula text the requests take ("2D4+1", "1D6+DB", "1D4+½DB", "3", "DB"); nothing at all is `NO_DICE` ("0"). `withHalfBonus` rewrites a damage bonus whole or half ("1D6+DB" ↔ "1D6+½DB"); text the picker can't show is left alone. The Item flyout uses it when the skill changes to or from Throw.
- **Connects to:** `dicePicker`, `flyouts/other/item.js`.
- **Could interact poorly with:** nothing (pure text). **Confirmed** by tests only.

### `customDice({ label, pickers })` (`dice-picker.js`)
- **How it works:** A wrapper (`rollbox-dice-custom`) with a full-width toggle button (`aria-expanded`) and a panel holding the pickers, closed at first. Opening syncs the pickers. Returns `{ element, button, open, sync() }`. Hidden while Simplified dice UI is on, through `hideWhenSimplified` (below).
- **Connects to:** `flyouts/check/sanity.js` (one button, two pickers), `flyouts/other/item.js` (one button, one picker with +DB).
- **Could interact poorly with:** nothing known. **Assumed.**

### `simplifiedDice()`, `setSimplifiedDice(on)` and `hideWhenSimplified(node)` (`dice-picker.js`; the last two exported)
- **How it works:** `simplifiedDice()` reads `rollboxSimplifiedDice` through `getSetting` inside `try` (off if it can't be read, e.g. in a test without it). `hideWhenSimplified` marks an element with `rollbox-simplified-hides` and sets its `hidden` attribute from the setting; the Custom sections and the flyouts' preset rows (Sanity presets, Item quick-picks) use it. `setSimplifiedDice` is the setting's `onChange`: it sets `hidden` on every `.rollbox-simplified-hides` in the document, so an open Sanity or Item flyout changes at once, without a reload. The value lines keep what they hold. `shared.css`'s `.rollbox-panel [hidden][hidden]` rule keeps it hidden whatever `display` a flyout's own rule gives it.
- **Connects to:** `shared/settings.js`; `flyouts/check/sanity.js`, `flyouts/other/item.js`; Foundry calls `onChange` on the client whose value changed (`client/helpers/client-settings.mjs`).
- **Could interact poorly with:** nothing known. **Assumed.**

### `blindToggle({ onChange })` and `withBlind(rows, toggle)` (`blind-toggle.js`; re-exported by `index.js`, used by `howRows`)
- **How it works:** `blindToggle` is a `<button class="rollbox-btn rollbox-blind">` reading "Blind", with `aria-pressed`; a click flips it and calls `onChange(on)` (nothing while disabled). Returns `{ element, on, disabled }`; the flyout can set `on` and `disabled` (the Check flyout turns Blind off and disables it on a combined roll) without `onChange`. `withBlind` lays the rows out in a column (`rollbox-how-rows`) with the toggle beside them (`rollbox-how`), stretched to their height. The text is turned sideways with CSS (`writing-mode: vertical-rl` and a 180° turn, so it reads bottom to top).
- **Connects to:** `flyouts/flyout.js` (`howRows`), which the Check flyout and the Other flyout's Item and Luck sections use; they read `on` into the request's `blind` option ([flyouts.md](flyouts.md)).
- **Could interact poorly with:** Foundry's global `button` styles: reset under `.rollbox-panel`. **Assumed.**

### `statusLine(className)` (`status-line.js`)
- **How it works:** A `<p class="rollbox-status …">` with `aria-live="polite"` and three methods: `missing(text)` (red: `rollbox-status-missing`), `note(text)` (plain) and `clear()`. Empty, it is hidden. Text only.
- **Connects to:** `sendSection` (`flyouts/flyout.js`), which makes every flyout's line and calls `missing()` while its send buttons are greyed out and `clear()` once they work (no summary of what will be sent); Assist makes its own and passes it in. The Opposed view's tie line is `note()` (worked-out information, like Assist's result block).
- **Could interact poorly with:** nothing. **Assumed.**

### `button(className, text, onClick)` (`button.js`; re-exported by `index.js` and `flyouts/flyout.js`)
- **How it works:** A `<button type="button">` with the class and text, and `onClick` on `click`: a button that never submits anything. The one button builder the flyouts and the shared controls use.
- **Connects to:** `dice-picker.js`; `flyouts/flyout.js` (which re-exports it to every flyout); `utils.js` (`element`).
- **Could interact poorly with:** nothing. **Assumed.**

### `glyphButton(className, icon, onClick, { text, textClass, label, tooltip })` (`button.js`; re-exported by `index.js` and `flyouts/flyout.js`)
- **How it works:** A `button()` showing a Font Awesome glyph (utils' `glyph`), with its words beside it (`text`, in a span with `textClass`) or for screen readers only (`label`, `aria-label`), and Foundry's tooltip (`data-tooltip`) when given. The one glyph button the flyouts use: Opposed's crosshair and ✕ buttons, Assist's target, ✕ and Add a character, Check's clear button.
- **Connects to:** `utils.js` (`glyph`, `element`); Font Awesome (Foundry's).
- **Could interact poorly with:** nothing. **Assumed.**

### `difficultyFor(value)`, `MANEUVER_GOALS`, `maneuverDice(ownBuild, opponentBuild)`, `buildOf(actor)`, `PICKED_FLAG`, `MELEE_REACH_DEFAULT`, `metresPerUnit(units)` (`rules.js`; `metresPerUnit` not re-exported by `index.js`)
- **How it works:** Pure data and arithmetic, each rule stated once; CoC7 rolls and judges every roll.
  - `difficultyFor(value)`: the difficulty for a number to beat (Keeper Rulebook p. 88): below 50 `"regular"`, 50 or more `"hard"`, 90 or more `"extreme"`.
  - `MANEUVER_GOALS`: the fighting maneuvers' goals (p. 105), `{ id, label }` in the order the flyouts show them: Restrain, Knock down, Disarm, Push away, Break free, Knock out.
  - `maneuverDice(ownBuild, opponentBuild)` → `{ dice, impossible, known }`: one penalty die per point of Build the opponent has over the one maneuvering, as a negative number (0, −1 or −2, as on CoC7's cards); three or more points over: `impossible`; a bigger character maneuvering gets no bonus die; a missing Build (`null` or `undefined`) gives `known: false` and no dice.
  - `buildOf(actor)`: the character's Build, CoC7's `system.attribs.build.value` as a number, or `null` when the sheet has none (guarded): the number `maneuverDice` compares, read the same way by the Action flyout's Maneuver, the alert and roll-requests' maneuver card.
  - `PICKED_FLAG`: `"pickedWeapon"`, the name of Rollbox's flag on a character holding the weapon picked in the Action flyout (its item id, or `"unarmed"`).
  - `MELEE_REACH_DEFAULT`: 1, the melee reach in metres: the Melee reach setting's default, and the reach used when the setting can't be read.
  - `metresPerUnit(units)`: metres in one of the scene units Foundry scenes use (m, ft, yd, km, mi and their long names, case and spaces ignored), or `null` for a unit not in the table; each caller decides what an unknown unit means.
- **Connects to:** `difficultyFor`: combat's notice cards (Stealth to the Roll to notice's difficulty, [combat.md](combat.md)) and the Assist split ([assist.md](assist.md)). `MANEUVER_GOALS`, `maneuverDice` and `buildOf`: the Action flyout's Maneuver tab ([action-flyout.md](action-flyout.md)), the being-attacked alert's Maneuver ([alert-flyout.md](alert-flyout.md)) and roll-requests' maneuver card (`maneuver.js`, [roll-requests.md](roll-requests.md)); `buildOf` reads CoC7's actor data. `PICKED_FLAG`: the Action flyout writes the flag (`weapons.js`) and combat's readied firearms read it (`readied-firearms.js`, [combat.md](combat.md)). `MELEE_REACH_DEFAULT`: the Action flyout's `rollboxMeleeReach` default (`attack.js`) and its reach (`weapons.js`), and combat's firing into melee (`situation.js`). `metresPerUnit`: `distance.js` (below), which every distance goes through.
- **Could interact poorly with:** nothing (pure). **Assumed.**

### `edgeDistance(from, to)`, `feetOf(measured)`, `distanceText(measured)`, `tokenCentre(token)` (`distance.js`); private `widthOf`, `FOOT_METRES`
- **How it works:** The one distance Rollbox measures between two tokens, on gridless scenes too. `edgeDistance` → `{ distance, units, metres } | null`: edge to edge, each token counted as a circle as wide as the token (`widthOf`: the placeable's `w`, else its document's width in grid spaces × `canvas.grid.size`), so centre to centre less each token's half-width (`tokenCentre`: where the token was moved to, `TokenDocument#getCenterPoint` of its stored `_source` x and y, because during a move's animation the document's `x`/`y` and `Token#center` still give the place before the move; else `Token#center`; also `combat/sight.js` `centreOf`), never below 0; in the scene's units (pixels ÷ `canvas.grid.size` × `canvas.grid.distance`), `units` the scene's label (`canvas.grid.units`, e.g. "ft"), `metres` the same in metres through `metresPerUnit` (null for a unit not in the table). Null when a token, its centre or the grid can't be read; a throw reads as null. `feetOf(measured)` → feet, or null without metres. `distanceText(measured)` → "4.5 ft", "12 ft" (one decimal under 10), or null. The rulebook leaves measuring to the table (combat distances are narrative, Keeper Rulebook p. 127), so edge to edge is the table's choice ([DESIGN.md, "Action flyout"](DESIGN.md#action-flyout)).
- **Connects to:** the Action flyout's target box ("6 ft away"), melee reach (`weapons.js` `distanceBetween`, `inReach`) and point-blank range (`target.js`, `feetOf`) ([action-flyout.md](action-flyout.md)); combat's notice distance (`notice-cards.js`) and firing into melee (`situation.js`) ([combat.md](combat.md)); Foundry's `canvas.grid` (`size`, `distance`, `units`), `TokenDocument#_source` (internal, registry) and `#getCenterPoint`, `Token#center`, `#w` (public).
- **Could interact poorly with:** CoC7's own attack card, which shows its own distance centre to centre: the two can differ by the tokens' half-widths (Rollbox ticks Point blank on CoC7's card when its edge-to-edge distance says so). Weapon ranges stay CoC7's, in yards. Non-round tokens are measured as circles. **Assumed.**

### `reloadKind(weapon)`, `reloadSource(weapon)`, `isReloadable(weapon)`, `saveReloadKind(weapon, kind)`, `RELOAD_FLAG`, `RELOAD_KINDS`; private `nameRule`, `COCID_RELOAD` (`reload-kind.js`)
- **How it works:** How a firearm reloads in combat (Keeper Rulebook p. 113): `"rounds"` (two a round: revolvers, derringers, single shots, bolt and lever rifles, shotguns), `"magazine"` (a clip or magazine in one round) or `"belt"` (two rounds). CoC7 keeps no field that says which, so `reloadSource` decides, in order: Rollbox's flag `flags.keepers-rollbox.reloadKind` (`RELOAD_FLAG`, read with `getFlag`) → `{ source: "flag" }`; the weapon's CoC ID (`flags.CoC7.cocidFlag.id`) in `COCID_RELOAD`, a table of every firearm with a capacity in CoC7 8.15's `en-wiki-weapons`, the Keeper items' `armor-and-weapons` and the Starter Set's `reference-items` compendiums (both spellings of ids the two compendiums write differently) → `"cocid"`; else `nameRule` → `"rule"` when sure, `"guess"` when not. `nameRule` reads the main skill as written (a name, or in a compendium a CoC ID): Machine Gun (not submachine) a belt; Submachine Gun, Assault, or CoC7's `auto` / `brst` a magazine; Handgun or Pistol a magazine unless the name says revolver, derringer or flintlock (sure only when the name says automatic, semi-auto, self-loading, magazine, clip, Luger, Glock, Beretta, Mauser, Browning or Desert Eagle); Rifle, Shotgun, Carbine or Musket two rounds; anything else two rounds, a guess. `isReloadable`: a weapon CoC7 marks ranged, not thrown, with a capacity (`system.bullets` > 0), and not on a Throw, Fighting, Brawl, Demolitions or Electrical skill (CoC7's compendiums mark shuriken, mace spray and dynamite ranged with no Thrown tick). `saveReloadKind`: `setFlag` the kind; true when saved or already so, false (one warning) when it couldn't be.
- **Connects to:** the Action flyout's Reload ([action-flyout.md](action-flyout.md), which saves a sure kind the first time); the setup check ([setup.md](setup.md), which saves the sure ones at login and asks the guesses).
- **Could interact poorly with:** a CoC7 update that renames compendium CoC IDs (those weapons fall back to the name rule). **Assumed.**

### `rightClickTargets(node, who)`, `targetOnly(token)`, `tokenFor(actor)` (`target-click.js`)
- **How it works:** a right click on any character anywhere in Rollbox targets them, for the Keeper and players. `rightClickTargets` adds a `contextmenu` listener to the node that shows the character: the browser's menu is prevented, the event stops there (so a card around it doesn't act too), and `targetOnly` makes that token the user's only Foundry target (`Token#setTarget(true, { releaseOthers: true })`, which fires Foundry's `targetToken` hook as a click with the Target tool does; a throw is one warning). `who` is the character (its token found by `tokenFor`) or a function giving the token (a turn-order row's combatant, a fight box's row). `tokenFor(actor)`: an unlinked token's own token (`actor.isToken`, `actor.token.object`), else one of the user's selected tokens of that character (`canvas.tokens.controlled`), else its first token on the viewed scene (`Actor#getActiveTokens`); `null` with none, and then nothing happens. Used by the panel (the one- and two-character sheets, the character cards, the players list; through `characterSheet` also the turn order's full card), combat (the turn order's rows, the Who's joining window's and the joining card's lines), Opposed (a side's name, a group side's names) and Assist (a character's row).
- **Connects to:** Foundry's `Token#setTarget`, `canvas.tokens.controlled`, `Actor#getActiveTokens`, `actor.isToken` / `actor.token.object` (Internal API registry, Foundry public).
- **Could interact poorly with:** a module that adds its own right-click menu to Rollbox's elements (none known); a player right-clicking a character with no token on the scene: nothing happens. Players may target any token they can see (Foundry). **Assumed**; seen in e2e (a character card, the sheet, a turn-order row, for the Keeper and the Player).

### `shared.css`
- **How it works:** Listed after the panel's own stylesheets (`panel.css`, `position.css`, `sheet-values.css`) and before every flyout's own file in `module.json` `styles`, so it is the base and a flyout's own rule of the same weight wins (the theme stylesheets come last and beat it too). Every rule is scoped under `.rollbox-panel` and uses the panel's palette variables (`panel.css`, [panel.md](panel.md)), so the Theme, Panel colour, transparency and size apply. It holds:
  - one rule that keeps anything `[hidden]` hidden (`.rollbox-panel [hidden][hidden]`, which outweighs any one-class rule, so neither the flyouts nor the panel need `[hidden]` lists);
  - **the theme's colours on Foundry's own controls:** Foundry colours placeholders and tick boxes from its interface theme, not the panel's, so every `input`, `select` and `textarea` in the panel sets Foundry's `--input-placeholder-color` to `--rollbox-placeholder` (and `::placeholder` takes it too), and every tick box and radio sets `--checkbox-background-color` to `--rollbox-box` and `--checkbox-disabled-color` to `--rollbox-disabled`; under the Light palette a checked one takes the accent (`--checkbox-checked-color`) instead of Foundry's orange (Foundry build 368 `foundry2.css`);
  - sections (`rollbox-section`: a column, 12px of space before each, no lines or headings), the muted line under a flyout's title (`rollbox-flyout-who`), the status line (red `--rollbox-bad` when something is missing), the action row with the highlighted main button (`rollbox-primary`: the accent mixed 45% into the panel's solid colour, 1.6 times as wide as the others);
  - the result (`rollbox-result`: a heading and indented lines per group, `rollbox-result-heading`, `rollbox-result-line`); the Difficulty and Dice buttons beside the Blind toggle narrowed so "Extreme" fits (`.rollbox-how .rollbox-segment`);
  - the generic pieces every flyout uses: buttons (`rollbox-btn`, also on the dice picker's buttons and steppers, the Custom button and the Blind toggle, which keep only their own size and place; the pressed look `--rollbox-pressed` with an accent border for `rollbox-tab[aria-selected]`, `rollbox-segment[aria-pressed]`, `rollbox-dice-button[aria-pressed]`, `rollbox-dice-toggle[aria-expanded]` and `rollbox-blind[aria-pressed]`; disabled in the theme's `--rollbox-disabled` text colour, not faded, so it stays readable), rows of buttons (`rollbox-segmented`), labelled lines (`rollbox-line`, `rollbox-line-label`), text boxes and drop-downs (`rollbox-input`), hints (`rollbox-hint`), lists with tick boxes or radios (`rollbox-list`, whose rows never shrink, and `rollbox-row`, whose inputs set Foundry's `--checkbox-size` to 14px so the glyph, 20px otherwise, doesn't hang below the row) and the trained/untrained divider (`rollbox-divider`);
  - the value line and its box, the Custom button and picker (their sizes; the look is `rollbox-btn`'s), and the Blind toggle (26px wide, the text turned sideways);
  - a selection that shows and goes at once: `.rollbox-panel button { transition: none }` and no outline on a mouse-focused button (`:focus:not(:focus-visible)`), since Foundry's `button { transition: 0.5s }` and its focus outline left a smaller, fading copy of the selection border on a deselected segment, tab or tile. The keyboard's focus ring (`:focus-visible`) stays; a theme that animates its own buttons (Art Deco's ribbons) sets its transition with a stronger rule.
- **Connects to:** `panel/panel.css` (variables); every flyout's CSS; Foundry's `--input-placeholder-color` and `--checkbox-*` variables.
- **Could interact poorly with:** Foundry's `modules` cascade layer and global styles ([DEVELOPING.md, "The panel and CSS"](DEVELOPING.md#the-panel-and-css)). Another module's button transitions inside the panel are switched off. Another module's CSS that styles `[hidden]` elements under the panel. A Foundry update that renames its placeholder or tick-box variables: those would take Foundry's colours again. **Assumed** until a look check.
