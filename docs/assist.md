# Assist (`scripts/assist/`)

What the Keeper's Assist button opens with two or more characters selected: Physical Human Limits, Keeper Rulebook p. 88–89 (summary p. 407). Several characters put their STR or SIZ together against something too big for any one of them: a rafter to lift, a door to hold shut, a creature to brace against. Rollbox works out who helps and who rolls, asks the rollers for an ordinary characteristic check at the worked-out difficulty, and posts one public Assist card saying who helps and who rolls. It doesn't read the rolls back: the Keeper reads the rollers' cards, and one success is enough (Void, 2026-11-14). Keeper only. Files: `index.js` (the menu, the card, the names-card column), `split.js` (the maths: who helps and who rolls), `assist.css`. No settings.

**Status key:** *Confirmed* only when the build guide's Internal API registry or changelog says so. Nothing in this part has been tried at the table yet, so everything is **assumed** unless stated otherwise.

## What the Keeper sees

A flyout like the other menus, in sections with space between them. Every control is inside it (Void, 2026-11-14): the names card beside it only shows each character's value (below, `assistColumns`). Top to bottom:

| Part | What it shows |
| --- | --- |
| Number to beat | a large editable value line (`docs/shared.md`), starting at 0. With targets marked it shows their Against values added together, captioned "STR against Zombie A + Zombie B"; with none, the typed number, captioned "STR against SIZ" (Use against Against). Typed text that isn't a whole number 0–999 turns red. Typing a number unmarks every target; unmarking the last target brings the typed number back |
| Use, Against | two toggles side by side: **Use** STR \| SIZ (what the characters put in, STR at first) and **Against** STR \| SIZ (which value of a target counts, STR at first; with no target it only names the typed number's characteristic). Switching Against unmarks a target without that value |
| Characters | every selected character in names-card order: a name toggle (name on the left, the value that counts on the right: the Use value, or the Against value for a target) and a narrow target button on the right, just wide enough for its crosshair (`fa-crosshairs`, accessible label "<name>: target"). All are included at first. Clicking a name leaves that character out (dashed, struck through, not counted at all); clicking again brings them back. Leaving a target out doesn't unmark it: it counts again as a target when brought back (Void, 2026-11-14). A left-out character's target button is greyed out. Only the target button marks or unmarks a character (and typing a number unmarks all): a target's row is tinted coral, it takes no part, and the targets' Against values add up to the number to beat. CoC7 creatures (actor type `creature`) start marked when they are selected (a character without the Against value isn't marked, and its target button is greyed out); the Keeper can unmark them. A character without the Use value shows "—" and takes no part |
| Result | "Assisting": one line per helper, name and "−20" ("No one" when nobody helps); "Rolling": one line per roller, name and "STR 60"; then one highlighted line, "Regular STR" on the left and "90% one succeeds" on the right. Or, instead, one red line saying what's missing or impossible, with Send greyed out: "Select at least one more token." (one token selected), "Include at least one more character." (nobody left to take part after leaving people out and marking targets), "Type the STR to beat." (typed text refused), "Target someone, or type the STR to beat." (no target and 0), "Too heavy even together." (no split works). The characteristic in them is the Against one |
| Label | optional text, placeholder "Label (optional), e.g. lift the rafter" |
| Send | Send to rollers (highlighted) and Cancel; then the result, one name per line: "Assist sent to:" / "Helen (Test)", "Rolled for you:" / "Belinda", then "Assist card posted." |

Selecting or deselecting tokens while it's open redraws it at once, keeping the toggles, the typed number, who is left out or marked (while still selected) and the label; a newly selected creature starts marked. A character deselected and selected again counts as new. With one token selected it stays open (the panel shows the mini sheet and its buttons, none pressed) with the red line. No Blind, no bonus or penalty dice: the difficulty is worked out.

## Code

### `registerAssist()` (`index.js`, called from `main.js` at `ready`)
- **How it works:** Returns `false` unless `isKeeper()` and `rollboxEnabled` is on. Otherwise `registerMenu("assist", { title: "Assist", render: renderAssist, staysOpen: true })`.
- **Connects to:** `mini-sheet/` (`registerMenu`, `docs/mini-sheet.md`: `staysOpen`, `selectionChanged`); `utils.js`.
- **Could interact poorly with:** nothing outside Rollbox. **Assumed.**

### `renderAssist(body, { actors, close, selectionChanged })` (`index.js`, exported)
- **How it works:** The menu host's render. Builds the whole menu from scratch. Its choices (Use, Against, the typed number, the sets of left-out, target and already-seen characters by uuid, the label) live in one module-level object: new when the menu opens (`selectionChanged` false), kept when it is drawn again for a new selection, so shift-clicking tokens updates it at once. On each draw, characters no longer selected are dropped from the three sets, and each character not seen before is added to `seen` and, if it is a CoC7 creature (`actor.type === "creature"`, CoC7 `system.json` `documentTypes.Actor`) with the Against value, marked as a target. Every change calls the context's `cardChanged()`, so the names card's column follows.
- **Connects to:** `MenuHost` (`docs/mini-sheet.md`: `selectionChanged`, `cardChanged`).
- **Could interact poorly with:** nothing known. A redraw while the Keeper is typing in the label loses the focus (the menu is rebuilt), but not the text. **Assumed.**

### `assistChoices(characters, against)` and `difficultyFor(left)` (`split.js`, re-exported from `index.js`)
- **How it works:** Pure functions, no Foundry or CoC7 calls (skill-values' `withLevels`, which they use, is arithmetic too). `characters` are `{ value, … }` in names-card order (the menu passes `{ actor, name, value }`); one without a number value takes no part. They are sorted lowest value first, with equal values keeping their order (a stable sort). For each number of helpers from none up to all but one: each helper takes their value off; what's left must stay above 0 (once it doesn't, more helpers only take more off, so the search stops) and every remaining character must be able to try it, i.e. what's left is no more than 100 + their value (p. 88). The difficulty is `difficultyFor(left)`: below 50 Regular, 50+ Hard, 90+ Extreme. The chance that at least one roller succeeds is 1 − the product of each roller's chance to fail, each roller's chance being their value, half or fifth (skill-values' `withLevels`, rounded down as CoC7 does), out of 100. The split with the best chance is used; a chance within 1e-9 of a better one counts as equal, so ties go to fewer helpers. Returns `{ helpers, rollers, left, difficulty, chance }`, or `null` when no split works ("Too heavy even together"), when nothing is to be beaten (0 or less), or with nobody taking part.
- **Rulebook rafter** (p. 88–89): 150 against Harvey 20, Cecil 40, Martin 45, Helen 60, Belinda 75 gives Harvey, Cecil and Martin helping, Helen and Belinda rolling at Regular with 45 left: 90% that one succeeds (1 − 0.40 × 0.25). With one or two helpers 130 or 90 is left (Extreme, about 37% and 32%); with four, nothing is left.
- **No helpers is a split too:** when everyone can try it alone and that gives the best chance (e.g. against 20, or two characters bracing against something light), nobody helps and everyone rolls; the result then reads "Assisting: No one" and the card says "Helping: no one." Without it a light load would read "Too heavy even together" (DESIGN.md Decisions, 2026-11-14).
- **The chance is an estimate** for choosing and for the Keeper's eye: it ignores criticals, fumbles and the 01 that always succeeds. CoC7 rolls and judges every real roll. Rollbox writes no dice or success-level code.
- **Connects to:** `AssistMenu` (`plan()`); skill-values' `withLevels`; the tests (`tests/assist.test.mjs`). `characters` are the participants only: targets and left-out characters are never passed.
- **Could interact poorly with:** nothing (pure). **Confirmed** by tests only.

### `assistColumns(actors)` (`index.js`, exported; registered as the menu's `columns`)
- **How it works:** The names card's value column while Assist is open: one column headed by the Use characteristic ("STR"), showing each participant's (and each left-out character's) Use value and each target that counts its Against value (`countsAsTarget`); when a target counts the other characteristic, the header reads "STR/SIZ". A missing value shows "—". It reads the same module-level choices as the menu. The names card has no controls.
- **Connects to:** `MenuHost.columns` and `drawCard` in `mini-sheet/` (`docs/mini-sheet.md`).
- **Could interact poorly with:** nothing outside Rollbox. **Assumed** until Void's look check (the "STR/SIZ" header reaches left into the title's room).

### `AssistMenu` (`index.js`)
- **How it works:** `whatSection()`: the number line (`valueLine` with `againstNumber`: a whole number 0–999, tidied, "007" → "7"; empty counts as 0) with its caption, the Use and Against toggles (`toggle`: the shared `segmented` row, buttons with `data-value` and `aria-pressed`, in a group labelled "Use" or "Against"), and one row per character (`nameRow`: the name toggle, `aria-pressed` true while included, and the target button, a narrow button just wide enough for its crosshair, `fa-crosshairs`, with the name toggle taking the rest of the row). `leaveOut` toggles a character in the left-out set (Void, 2026-11-14: only the target button marks or unmarks): only the target button marks or unmarks, so a target left out stops counting and counts again as a target when brought back. `mark` toggles the target set and does nothing for a left-out character; `typed()` stores the typed text and unmarks every target, unless the line just shows the targets' sum (clicking away from it changes nothing). `countsAsTarget` is the one rule for a target that counts: marked, not left out, and with the Against value (a marked character without it, after Against is switched, stays marked and counts again when switched back). A creature deselected and selected again starts marked again, even after the Keeper unmarked it (the menu forgets characters no longer selected). `plan()` reads who takes part (everyone selected who isn't left out or marked as a target and has the Use value, through `skill-values/`' `characteristics`), the targets and the number to beat (their Against values added together, or the typed number; null while the typed text is refused), and calls `assistChoices` when someone takes part and the number is above 0. `update()` marks the toggles and rows, writes the line and caption, draws the result or the red line (`missing()`, in that order: fewer than two selected, nobody taking part, refused text, nothing to beat, no split) and greys out Send while something is missing (Void, 2026-11-14), then calls `cardChanged()`.
- **Adding the targets together** is the Keeper's ruling (Void, 2026-11-14): the rule only describes investigators combining (p. 88–89).
- **Send to rollers** (`send()`): `checkRequest({ checks: [{ kind: "characteristic", name: "str" | "siz" }], difficulty, label })`, sent with `send(request, rollers, { mode: "whisper" })` (`docs/roll-requests.md`): each roller with a player gets CoC7's whispered request ("… make a Hard STR · lift the rafter roll"; Regular reads "STR · …"), each NPC roller is rolled privately for the Keeper with a Keeper's note naming the label, as for any check. With no label typed the label is "Assist", so players read "STR · Assist" (or "SIZ · Assist", "Hard STR · Assist"; Void, 2026-11-14). Then, if at least one roller was asked or rolled, the Assist card. A roller `send()` skipped (e.g. a failure) isn't named on the card; the result says why. The result (`runSend` and `showResult`, `docs/shared.md`): "Assist sent to:" with each player's roller on its own line, "Rolled for you:" with each NPC roller, "Not sent:" with reasons, then "Assist card posted."
- **Cancel** closes the menu (the host's `close()`).
- **Connects to:** `roll-requests/` (`checkRequest`, `send`), `skill-values/` (`characteristics`), `shared/` through its `index.js` (`valueLine`, `captioned`, `valueBox`, `statusLine` for the red line under the result, passed to `sendSection` for Send to rollers and Cancel (`data-keep`, never greyed out), `button`, `segmented`, `runSend`, `showResult`, `DIFFICULTY_LABELS`); `utils.js` (`element`, `actorKey`, `NO_VALUE`).
- **Could interact poorly with:** CoC7's own handling of each request is as for the Check menu (BUILD-GUIDE "CoC7 integration"): a player can change the difficulty in CoC7's roll dialog (Gap 9). **Assumed.** Creature sheets made by other modules or importers with another actor type aren't marked automatically; the Keeper marks them. **Assumed.** Two tokens of one linked actor count as one character (the panel keeps each actor once), so two linked "Zombie" tokens give one target; unlinked tokens are separate. **Assumed.**

### `assistCardHtml({ use, against, label, left, difficulty, helpers, rollers })` and `postCard` (`index.js`)
- **How it works:** The public Assist card: "Assist", the label (italic, if any; the card shows only the Keeper's own text, not "Assist"), "STR against SIZ: 45 left, **Regular STR**." (Use against Against), "Helping: Harvey, Cecil, Martin." (or "no one"), "Rolling: Helen, Belinda.", and "One success is enough." Every name and the label go through `escapeHtml`. `postCard` posts it with `ChatMessage.create({ speaker: { alias: <the Keeper's user name> }, content })`, with no `whisper`, so everyone sees it; the alias keeps it from being spoken by a selected token. It is static: Rollbox doesn't watch or read the rolls (FUTURE.md idea 12). The card doesn't show the number they're up against or name the targets (a creature's STR stays the Keeper's), only what's left.
- **Connects to:** Foundry's `ChatMessage.create` (public API); `assist.css` styles it in the chat log (`.rollbox-assist-card`, outside the panel, so players' clients style it too; the CSS is loaded for everyone, but Rollbox draws nothing for players).
- **Could interact poorly with:** chat-styling modules and CoC7's chat CSS: the card uses plain `h3` and `p`. **Assumed.** Modules that change every chat message's speaker. **Assumed.**

### `assist.css`
- **How it works:** Listed in `module.json` `styles` after `shared.css`, which gives the generic button look (`rollbox-btn`) to the toggles, name and target buttons, the label box, the result line, the sections, value line, status line and action buttons. Flyout rules are under `.rollbox-panel` and use only the panel's `--rollbox-*` variables, so Panel colour, transparency and size apply, with the theme's coral (`--rollbox-target`, `docs/mini-sheet.md`) for targets. A left-out row is dashed and struck through, a target row tinted coral. The target button is narrow (`flex: none`, its icon with 7px padding each side), as tall as the name row. The character list shows ten names before it scrolls, sized by rows, not pixels (Void, 2026-11-14): `--rollbox-row-height` on the list is a button's border, padding and one line (`calc(8px + 1.3 × --font-size-11)`, so it follows Foundry's font size), every row is exactly that tall, and the list's `max-height` is `10 × --rollbox-row-height + 9 × --rollbox-row-gap`. The result's difficulty-and-chance line is tinted with the accent. The chat card's rules are under `.rollbox-assist-card`.
- **Connects to:** `mini-sheet/mini-sheet.css` (variables), `shared/shared.css`.
- **Could interact poorly with:** Foundry's global `button` and `input` styles: overridden under `.rollbox-panel` in the `modules` cascade layer (BUILD-GUIDE "The panel and CSS"). **Assumed** until Void's look check.
