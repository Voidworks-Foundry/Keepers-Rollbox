# Mini sheet (`scripts/mini-sheet/`)

The Keeper's panel directly on top of Foundry's players list (the latency and FPS card): the mini sheet for one selected character, the names card for two or more, and beside it the buttons that open the Check, Sanity, Item, Opposed and Assist menus. Its look follows the personal Theme (Dark or Light), Panel colour, transparency and size settings. Keeper only, with the personal switch on. Files: `index.js` (hooks, selection, placement, the Appearance settings' effects), `theme.js` (the themes and the colour maths), `cards.js` (the two cards), `menu-host.js` (buttons, flyout, `registerMenu`), `mini-sheet.css` (the panel and both themes' palettes), `settings.js`.

**Status key:** *Confirmed* only when the build guide's Internal API registry or changelog says so. Nothing in this part is confirmed yet, so everything is **assumed** unless stated otherwise.

## Code

### `registerMiniSheet()` (`index.js`, called from `main.js` at `ready`)
- **How it works:** Returns `false` at once unless `isKeeper()` is true and `rollboxEnabled` is on, so players never read the setting and run no Rollbox code. Otherwise resets the part's state and installs six hooks (below), then returns `true`. Draws nothing at `ready`: nothing can be selected yet, and the first `controlToken` draws the panel. The panel's DOM is built the first time something is selected.
- **Connects to:** `utils.js` (`isKeeper`, `getSetting`); setting `rollboxEnabled` (user scope).
- **Could interact poorly with:** nothing at start-up. **Assumed.**

### Selection and redraw (`scheduleRedraw`, `selectedActors`, `redraw`, `index.js`)
- **How it works:** `controlToken`, `deleteToken`, `canvasReady` and `updateActor` (for a shown character) only ask for a redraw on the next animation frame (`requestAnimationFrame`); further calls before it runs are absorbed, so a box-select that fires the hook once per token draws once. The redraw reads `canvas.tokens.controlled`, takes each token's `actor`, leaves out tokens without one and keeps each character once (by uuid, so two tokens of one linked actor show once; unlinked tokens have their own actors and show separately), in selection order. None: the panel hides and any open menu closes. One: the mini sheet. Two or more: the names card, drawn over an invisible mini sheet of the first character (`sheetGhost`, below). No upper limit. The menu host gets the characters first (below), then the card is drawn (`drawCard`), so the names card's columns match the menu that is open after the change. A guarded read: if the canvas or its token layer is missing, nothing is selected.
- **Connects to:** `cards.js`, `menu-host.js`; Foundry's `canvas.tokens.controlled`.
- **Could interact poorly with:** modules that control tokens in bulk (e.g. selecting every token of a folder): still one redraw per frame. **Assumed.** `updateActor` from another user's change while a menu is open: the card is redrawn, the menu is not (the selection didn't change). **Assumed.**

### `attach()` (`index.js`, also the `renderPlayers` hook)
- **How it works:** Inserts the panel as a sibling just before `#players` in `#ui-left-column-1`, unless it's already there. Not inside `#players`, because Foundry replaces that element's contents each time it renders. If `#players` is missing, the panel isn't shown and one `console.warn` is logged.
- **Connects to:** Foundry's players list (`ui.players`, `aside#players`, build 368).
- **Could interact poorly with:** modules or themes that move, restyle or replace the players list or the left column (e.g. UI overhaul modules): the panel follows `#players` wherever it is, but its position and look were designed for Foundry's own layout. **Assumed.** CoC7 adds the world era inside `#players` on `renderPlayers`; Rollbox doesn't touch it. **Assumed.**

### `onTearDown()` (`index.js`, the `canvasTearDown` hook)
- **How it works:** On a scene change Foundry clears the selection without firing `controlToken`, so the panel hides at once and any pending redraw is cancelled. `canvasReady` then draws whatever is selected on the new scene (normally nothing).
- **Connects to:** Foundry's `Canvas#tearDown` (build 368, `canvasTearDown`).
- **Could interact poorly with:** nothing known. **Assumed.**

### `miniSheet(actor)` (`cards.js`, re-exported from `index.js`)
- **How it works:** One character: portrait (`actor.img`, or Foundry's mystery-man), name, occupation (`system.infos.occupation`) and owner joined by " · " (an occupation-less character shows only the owner; an NPC shows "NPC", e.g. "Steward · NPC", because "NPC · Keeper rolls" was cut off there), and a button that opens the full sheet (`actor.sheet.render(true)`, guarded). HP and MP as value/max with a bar; SAN with a bar against its max (99 if the sheet has none); Luck with a bar against 99; the eight characteristics, four to a row, in sheet order. Values come from `skill-values/` (`characteristics`, and `attributes` found by key, `lck` and `san`, never by their order) and `system.attribs.hp` / `.mp`; a missing value shows "—" (`NO_VALUE`, `utils.js`). All text is set with `textContent`, so a name with HTML in it shows as typed. A name too long for the card is cut off with "…", so the full name is also its hover tooltip (`title`), here and on the names card (`nameLine`).
- **Connects to:** `skill-values/index.js`; `roll-requests/index.js` (`ownersOf`); CoC7's data paths (build guide, "Actor and item data"). The Opposed roll shows one for each side (`opposed-roll/`).
- **Could interact poorly with:** CoC7 sheets that hide characteristics or attributes, or creatures without HP/MP/SAN: the missing values show as dashes. **Assumed.** A sheet that can't render (the sheet class missing or throwing): one warning (`warn()`, `utils.js`), nothing else. **Assumed.**

### `namesCard(actors, columns)` and `NAMES_COLUMNS` (`cards.js`)
- **How it works:** Two or more characters: a header ("N selected" and one heading per value column) and one row each with a small portrait, name, owner and the column values. Information only: no controls (Void, 2026-11-14: every control lives in the open menu). The columns follow the open menu: with no menu, Check or Opposed, SAN and Luck (`NAMES_COLUMNS.san`, `.luck`; Luck is there for the group Luck roll, the lowest Luck rolls, p. 89-90); with Sanity open, SAN alone; with Assist open, Assist's own column (`assistColumns`, `docs/assist.md`: "STR" or "SIZ", the Use value for participants and the Against value for targets). A column is `{ label, value(actor), className? }`; cells get `rollbox-names-value` plus the column's class when it has one (`rollbox-names-san`, `rollbox-names-luck`). A value that is missing, or a column that throws, shows "—". The header grid has one 30px track per column; a longer heading ("STR/SIZ") reaches left into the title's room. The list shows ten rows before it scrolls, sized by rows, not pixels (Void, 2026-11-14; 365px still scrolled at nine): `--rollbox-row-height` on the list is a row's padding plus its two lines at a fixed line height (`calc(6px + 1.25 × (--font-size-12 + --font-size-10))`, so it follows Foundry's font size), every row is exactly that tall, and the list's `max-height` is `10 × --rollbox-row-height + 9 × --rollbox-row-gap`.
- **Connects to:** as `miniSheet`; `MenuHost.columns` and `drawCard` (`index.js`) choose the columns.
- **Could interact poorly with:** nothing known. **Assumed.**

### `sheetGhost(actor)` (`cards.js`)
- **How it works:** With two or three selected the names card is as tall as the one-character mini sheet, so the buttons beside it line up the same way; more rows make it taller (Void, 2026-11-14). `sheetGhost` is the first character's `miniSheet` with its `rollbox-sheet` class swapped for `rollbox-sheet-ghost`, no `aria-label`, `aria-hidden="true"` and `inert`. `redraw()` puts it in the card slot before the names card; `mini-sheet.css` makes the slot one grid cell holding both, and the ghost `visibility: hidden` with no pointer events. The cell is as tall as the taller of the two and the names card stretches to fill it, so its height always matches the real mini sheet's, whatever Foundry's fonts.
- **Connects to:** `miniSheet`, `redraw()`.
- **Could interact poorly with:** nothing known: it is hidden from sight, screen readers, the mouse and the keyboard; its portrait is the same image the names card already loads. **Assumed** until Void's look check.

### `ownerText(actor)` (`cards.js`, not exported)
- **How it works:** The player owners' names from roll-requests' `ownersOf` (CoC7's `actor.owners`, non-GM users with OWNER), joined with ", "; "NPC · Keeper rolls" when there are none (Rollbox rolls those for the Keeper); empty when CoC7's `owners` can't be read.
- **Connects to:** `roll-requests/index.js` (`ownersOf`), so the panel and the requests agree on who is an NPC.
- **Could interact poorly with:** a character owned by a player who is offline still shows that player: requests are still whispered to them. **Assumed.**

### `menusFor(count)`, `MENUS` (`menu-host.js`, not exported)
- **How it works:** One character: Check, Sanity, Item. Two: Check, Sanity, Opposed, Assist. Three or more: Check, Sanity, Assist. `MENUS` holds each menu's button label, Font Awesome icon (`fa-dice-d20`, `fa-brain`, `fa-gun`, `fa-right-left`, `fa-people-carry-box`) and default flyout title. With two selected the column holds four buttons and reaches above the card (accepted, DESIGN.md "Layout").
- **Connects to:** DESIGN.md, "Layout by number of tokens selected".
- **Could interact poorly with:** nothing. **Assumed.**

### `registerMenu(id, { title, render, layout, staysOpen, columns })` (`menu-host.js`, re-exported from `index.js`)
- **How it works:** How each menu part plugs in: `id` is `check`, `sanity`, `item`, `opposed` or `assist`; `title` replaces the flyout's default heading; `render(body, { actors, close })` fills the flyout's body, which is emptied first. It is called when the menu opens and again when the selection changes while it is open (so it must build from scratch), but not when only a shown character's data changes. `actors` is a copy of the selected characters; `close()` closes the menu; `selectionChanged` is false when the menu opens and true when it is drawn again for a new selection, so a menu can carry its own choices over (Assist keeps its toggles, number, targets and label while tokens are shift-clicked); `cardChanged()` asks the panel to draw the names card again, for a menu whose `columns` changed. `columns(actors)` (Assist): the names card's value columns while the menu is open (see "Names card columns" below). `staysOpen` (Assist): the menu stays open while anything is selected, even when the selection no longer offers its button (Assist with one token says itself that another is needed); no button is then shown pressed, and the button comes back pressed when it is offered again. With nothing selected it closes like any menu. `layout` (`LAYOUTS`): `"flyout"` (default) or `"replace"`: the menu is drawn in the stage, in the card's place, with no title of the host's, while the card and the button column hide (for the Opposed roll). Registering an id again replaces the earlier menu. An unknown id or layout, or a missing `render`, is refused with a warning (returns `false`). A flyout `render` that throws leaves the flyout with its title and logs one warning; a `replace` one that throws logs one warning and closes, so the card and buttons come back.
- **Connects to:** every menu part, which calls it from their own `register…()`.
- **Could interact poorly with:** nothing outside Rollbox. **Assumed.**

### Request buttons' height (`mini-sheet.css`)
- **How it works:** One fixed height, set in CSS and never by a script (Void, 2026-11-14): `--rollbox-button-height` on `.rollbox-panel` is worked out from two constants, `calc((var(--rollbox-sheet-height) - 2 * var(--rollbox-button-gap)) / 3)`, so three buttons and the two gaps between them equal the one-character mini sheet at 100% Panel size (`--rollbox-sheet-height`, 182px, measured in Chromium with Foundry's own stylesheet and fonts; `--rollbox-button-gap`, 6px, which the button column's `gap` also uses): 56.67px. The button column is aligned to the card's bottom; with two tokens the fourth button reaches above the card, and a taller names card never stretches or squishes them (`flex: none`).
- **Connects to:** `.rollbox-button { height: var(--rollbox-button-height); flex: none }`, `.rollbox-buttons { gap: var(--rollbox-button-gap) }`; the Panel size scales them with the rest of the panel.
- **Could interact poorly with:** a Foundry font or font size that makes the mini sheet taller or shorter than 182px: the three buttons then no longer exactly match it (they keep their size). **Assumed** until Void's look check.

### Names card columns (`drawCard`, `index.js`; `MenuHost.columns`, `menu-host.js`)
- **How it works:** `redraw()` sets the shown characters, updates the menu host, then calls `drawCard(true)`. `drawCard` draws the mini sheet for one character; for two or more it asks `MenuHost.columns(actors)`: the open menu's own `columns` (Assist), SAN alone for Sanity (`MENU_COLUMNS`), or null for SAN and Luck. A menu `columns` function that throws gives the default with one warning. The host calls `drawCard()` (its `onCardChange`) when a menu opens or closes, and whenever a menu calls its render context's `cardChanged()` (Assist does on every change). Without `force`, the card is drawn again only when the characters or the column headings or values changed, so typing in a menu doesn't rebuild the card or reset its scroll.
- **Connects to:** `namesCard`, `MenuHost`, `registerMenu`'s `columns`.
- **Could interact poorly with:** nothing outside Rollbox. **Assumed.**

### `MenuHost` (`menu-host.js`)
- **How it works:** Owns the button column, the flyout and the stage. `update(actors)` redraws the buttons for the selection; an open menu stays open while its button is still offered, or while anything is selected for a `staysOpen` menu (`offers`), and is redrawn only if the selection changed (with `selectionChanged: true`); otherwise it closes. Clicking a button opens its flyout to the right of the buttons and sets the button's `aria-pressed="true"`; clicking the same button again closes it; clicking another switches. Until a menu is registered its flyout shows only its title.
  - **Stage**: `new MenuHost(side, cardSlot, onCardChange)` puts an empty, hidden `.rollbox-stage` just after the card slot (the card slot is required). A `"replace"` menu hides the card slot and the button column (the `hidden` attribute), shows the stage and renders into it (`drawStage`). `close()` (Cancel, the selection losing its button, or nothing selected) empties and hides the stage and shows the card and the buttons again (`leaveStage`). The panel keeps redrawing the hidden card on selection and actor changes, so the card is current when it comes back.
- **Connects to:** `registerMenu`.
- **Could interact poorly with:** nothing known. **Assumed.**

### Panel transparency: `TRANSPARENCY`, `applyTransparency(value)`, `setOpacity` (`index.js`)
- **How it works:** The setting `rollboxTransparency` (0–70%, default 25) sets one CSS variable, `--rollbox-opacity`, on the panel: 25% see-through is `75%`. `mini-sheet.css` builds every background from it with `color-mix(in srgb, <Foundry's --color-cool-5> 75%, transparent)`, so only the backgrounds of the cards, buttons and menus change; `opacity` is never set, so text and icons stay fully readable. The panel reads the setting when it is built; the setting's `onChange` calls `applyTransparency`, which changes it at once (no reload). Out-of-range values are clamped; an unreadable setting gives the default.
- **Connects to:** `settings.js` (`onChange`); `mini-sheet.css`; Foundry's settings `onChange` (called on this user's client when the value changes, build 368 `client-settings.mjs`).
- **Could interact poorly with:** browsers without `color-mix()` (Foundry v14's Electron and current browsers have it): the backgrounds would be dropped. **Assumed.** The pressed and hovered buttons stay solid on purpose. The default 25% is the panel's original look, Foundry's 75%-opaque `--color-cool-5-75`. In the Light theme the same setting lets half as much through (`mini-sheet.css`).

### Theme and Panel colour: `applyTheme(theme)`, `applyColor(color)`, `setTheme` (`index.js`); `shownColor`, `flippedColor`, `hexColor`, `normalTheme`, `toHsl`, `THEMES`, `DEFAULT_THEME`, `DEFAULT_COLOR` (`theme.js`)
- **How it works:** Two settings together. `rollboxTheme` ("dark" or "light", default dark) picks the palette: `setTheme` toggles `rollbox-theme-light` on the panel, and `mini-sheet.css` redefines every palette variable under it (below). `rollboxColor` (default `#0b0a13`, Foundry's `--color-cool-5`, the panel's original background) is the tint within the theme: `setTheme` sets `--rollbox-color` to `shownColor(color, theme)`, the colour itself when the theme's text reads well on it, otherwise its hue and saturation at the nearest HSL lightness that does (a binary search). "Reads well" is by WCAG relative luminance: at most 0.05 under Dark, at least 0.57 under Light, so every text colour of the theme, down to its placeholder, has 4.5:1 or more on the solid colour (WCAG AA). The setting keeps what the Keeper picked. `mini-sheet.css` takes the solid background from `--rollbox-color` (`--rollbox-bg-solid`) and the transparency mix applies on top. `hexColor` accepts Foundry's `Color` (a Number whose string is `#rrggbb`) or a `#rrggbb` string; anything else gives the default.
- **Switching the theme** (`applyTheme`, the theme setting's `onChange`; Void, 2026-11-14): the palette switches at once and the Panel colour's lightness flips to suit the new theme, keeping its hue and saturation: `flippedColor` mirrors the HSL lightness (L → 100 − L), so a dark navy becomes a light navy-tinted colour and back, then keeps it readable for the theme as above. The flipped colour is saved to `rollboxColor` with `game.settings.set` (`saveColor`: called at once, and a throw or a refused save is one `warn()`, the panel keeping the flipped colour until reload), so Configure Settings shows it and the Keeper can pick any colour from there; that setting's own `onChange` (`applyColor`) then redraws. A colour that already suits the new theme is left alone, so a switch seen twice (two screens of one Keeper) never flips it back. Only on the Keeper's client: a player's own theme change does nothing.
- **Connects to:** `settings.js` (`onChange` of both); `mini-sheet.css`; every menu's CSS, which only uses the panel's `--rollbox-*` variables, so the menus and the opposed view follow the theme and the colour; Foundry's `game.settings.set` (a failure is logged and the setting stays; the panel shows the flipped colour until a reload).
- **Could interact poorly with:** Configure Settings saving the theme and the colour in the same Save: whichever Foundry saves last wins (if the theme is saved after the colour, the new colour is flipped). **Assumed.** With a high transparency, what shows through from the canvas also affects how readable the text is; the Light theme lets half as much through for the same setting. **Assumed.** Foundry's tick boxes and placeholders take the theme's colours through Foundry's own variables (`docs/shared.md`); a Foundry update that renames them would leave Foundry's colours. **Assumed.**

### Panel size: `SCALE`, `applyScale(size)`, `setScale` (`index.js`)
- **How it works:** The setting `rollboxScale` (80–150%, default 100) scales the whole panel element (cards, buttons, flyout and the opposed view's stage are all inside it) with `transform: scale()` and `transform-origin: left bottom`. A transform doesn't change the panel's place in the left column, so the bottom-left corner stays where it was, directly on top of the players list, and the panel grows up and to the right over the canvas, never over the list. At 100% no transform is set, so the default panel is exactly as before. It also sets `--rollbox-scale` (e.g. `1.2`), which `mini-sheet.css` uses to keep the flyout's height at 70% of the screen whatever the size. Out-of-range values are clamped. Read when the panel is built; `onChange` calls `applyScale` at once.
- **Connects to:** `settings.js` (`onChange`); `mini-sheet.css`.
- **Could interact poorly with:** anything inside the panel with a `max-height` in `vh` must divide it by `--rollbox-scale`, or it can reach past the top of the screen at large sizes; the flyout and the opposed card (`opposed-roll.css`) both do. **Assumed.** Foundry's UI scale applies too (the panel is in the scaled column), so the two multiply. **Assumed.** A transform makes the panel a stacking context; nothing in Rollbox uses `position: fixed` or z-index across it. **Assumed.**

### `mini-sheet.css`
- **How it works:** Listed in `module.json` `styles`; every class starts `rollbox-`. The card slot is one grid cell (`display: grid`, every child at `grid-area: 1 / 1`), so the names card and the ghost mini sheet overlap. The stage of a "replace" menu is a row (`width: max-content`) that starts where the card was and runs to the right over the canvas, bottoms aligned; the card slot, the button column and the stage stay hidden through `shared.css`'s `.rollbox-panel [hidden][hidden]` rule (only `.rollbox-panel[hidden]` itself has its own). Sizes are variables on `.rollbox-panel`: `--rollbox-width` (200px), `--rollbox-gap` (8px), `--rollbox-radius` (8px), `--rollbox-col` (30px, one names-card value column; `cards.js` sets only `--rollbox-cols`, how many), `--rollbox-sheet-height` and `--rollbox-button-gap`, and `--rollbox-button-height` worked out from them. The panel is 200px wide in the left column with `margin-top: auto` (the column spreads its children with `space-between`; without it the panel would float to the middle). Its buttons (56 wide) and flyout (320px) are absolutely positioned to its right, bottoms aligned with the card (`bottom: 0`), so the column keeps its width and they lie over the canvas. The buttons have one fixed height, `--rollbox-button-height` (56.67px, a constant), and `flex: none`, so they never stretch or squish (Void, 2026-11-14): three fill the one-character mini sheet's height, four (two tokens) reach up above the card, and a taller names card or flyout changes nothing about them. The column has `pointer-events: none`; the cards, buttons and flyout turn them back on.
  - **The two palettes**, on `.rollbox-panel` (Dark, the default) and `.rollbox-panel.rollbox-theme-light` (Light), every part's CSS uses only these: `--rollbox-bg-solid` and `--rollbox-bg` (the Panel colour, solid and at the transparency's alpha; Light lets half as much through: `calc(50% + opacity / 2)`), `--rollbox-text`, `--rollbox-text-strong`, `--rollbox-text-muted`, `--rollbox-placeholder`, `--rollbox-disabled`, `--rollbox-border`, `--rollbox-border-hover`, `--rollbox-accent` (borders and fills) and `--rollbox-accent-text` (text in the accent colour, e.g. the Attacker tag), `--rollbox-bad` (the red of what's missing), `--rollbox-target` (Assist's coral), `--rollbox-defender` (the Defender tag's blue), `--rollbox-box` (an empty tick box or radio), `--rollbox-cell` (button and cell fill), `--rollbox-track` (bar tracks) and `--rollbox-pressed` (a pressed button or selected row: the solid colour on Dark, tinted with the accent on Light). Dark keeps Foundry's own players-card and scene-control colours (`--color-cool-5`, `--color-cool-4`, `--color-cool-3`, `--color-warm-2`) and fixed light text (`--color-light-1/2/4`), with fallbacks. Every text colour has at least 4.5:1 contrast on each theme's default solid colour and on any colour `shownColor` allows (checked with a script; the worst case is the placeholder at the luminance limit); disabled text and the empty tick box at least 3:1 on the defaults. The values are in the file.
  - The flyout's `max-height` is `calc(70vh / var(--rollbox-scale, 1))`. The HP, MP, SAN and Luck bars use `--rollbox-bar-hp`, `--rollbox-bar-mp`, `--rollbox-bar-san` and `--rollbox-bar-luck` (the design mockup's colours, the same under both themes). `.rollbox-flyout-title` is a menu's title: the flyout's, and the Opposed roll card's.
- **Connects to:** Foundry's stylesheet variables (build 368 `foundry2.css`). Foundry loads module styles into its `modules` cascade layer, after its own and CoC7's.
- **Could interact poorly with:** Foundry's light interface theme: the players card turns light; the panel follows Rollbox's own Theme setting, not Foundry's. **Assumed.** UI scale: the panel is inside the scaled left column, so it scales with it. **Assumed.** Modules that put something else at the bottom of the left column, or between the scene controls and the players list. **Assumed.**

## Hooks, overrides, keybindings
- Hooks (Keeper's client, switch on): `controlToken`, `deleteToken`, `canvasReady` (redraw next frame); `canvasTearDown` (hide at once); `renderPlayers` (put the panel back before `#players`); `updateActor` (redraw if that character is shown). All Foundry public hooks.
- Class overrides: none.
- Keybindings: none.

## Settings (`settings.js`)
Two exports. `PANEL_SETTINGS` holds the switch, which `settings.js` puts first in its "Keeper's Rollbox" section, followed by the shared Simplified dice UI setting (`docs/shared.md`). `APPEARANCE_SECTION`, title "Appearance", holds Theme, Panel colour, Panel transparency and Panel size in that order, with `master: "rollboxEnabled"` so they dim while the panel is off (`docs/settings.md`).
- Master `rollboxEnabled` ("Show the Rollbox panel"; hint "When you select tokens, a small panel above the players list lets you request rolls from those characters. Only you see it."; user scope, Boolean, default true, Personal note). Requires a reload, because `registerMiniSheet()` and `registerCheckMenu()` read it once at `ready`.
- `rollboxTheme` ("Theme"; hint "Dark or Light: the panel's text, buttons and highlights, each tuned to stay readable. Switching it also turns the Panel colour light or dark, keeping its tint."; user scope, String with `choices` `{ dark: "Dark", light: "Light" }`, which Configure Settings shows as a drop-down; default `dark`; Personal note; `requiresReload: false`, applied at once through `onChange` (`applyTheme`); `reset: true`). The key is permanent once released.
- `rollboxTransparency` ("Panel transparency"; hint "How see-through the panel, its buttons and its menus are. Text stays fully readable."; user scope, Number, `range` 0–70 step 5, which Foundry v14 shows as a slider (`SettingsConfig` turns `type: Number` with `range` into a `NumberField` with min, max and step); default 25; Personal note; `requiresReload: false`, applied at once through `onChange`; `reset: true`).
- `rollboxColor` ("Panel colour"; hint "Background colour of the panel, its buttons and its menus, within the theme: it is shown darker or lighter where the theme's text needs it."; user scope, `foundry.data.fields.ColorField` (not nullable), which Configure Settings shows as Foundry's colour picker (a text box and a colour swatch), or a plain String if the field is ever missing; default `#0b0a13`; Personal note; `requiresReload: false`, applied at once through `onChange`; `reset: true`).
- `rollboxScale` ("Panel size"; hint "Size of the panel, its buttons and its menus."; user scope, Number, `range` 80–150 step 10 (a slider); default 100; Personal note; `requiresReload: false`, applied at once through `onChange`; `reset: true`).

`reset: true` puts a small Reset button beside the setting in Configure Settings (`docs/settings.md`).
